### 수정 힌트
- post_id 가 안정적 ID 모양이 아니면(공백 등) — title 을 post_id 로 쓴 게 아닌지 확인. post_id 는 URL/href 안의 숫자 ID 같은 걸 써라.
- published_at ISO8601 파싱 실패 — 날짜 문자열 형식을 먼저 맞춰라. "2026.04.17" 면 `["replace",".","-"]` 후 `["date_only_to_iso","+09:00"]`, 또는 `["iso8601",["%Y.%m.%d"],"+09:00"]`.
- 본문 0자 / <100자 — article.content 의 selector 가 틀린 것. 위 "글 페이지 HTML 샘플" 에서 본문 컨테이너를 다시 찾아라. **글 본문이 정적 HTML 에 통째로 없으면(SPA): (a) digest 의 "글 본문 JSON API 후보"(article_sample.api_candidates)가 있으면 article 을 그 API 로 — fetch_kind:"json" + url_template + content:[{from:"json", path:<body_field_path>}]. (b) 없으면 strategy 를 "playwright_html" 로 바꾸고 article.wait_selector 에 본문 컨테이너 CSS selector 를 넣어 렌더 완료를 기다려라 (list.wait_selector 와 분리 — article 에 없으면 본문 fetch 시 wait 안 함, list 폴백 X).**
- **본문 검증 article_body_len 가 *직전 2회 이상* FAIL 했고 글 페이지 HTML 에 진짜 "글 본문" 자체가 부재 — 사이트가 본문 없는 종류 (검색결과 SERP / 이상형월드컵·인터랙티브 게임 디렉토리 / 외부 host 행 aggregator / canvas-only SPA 등): `article.body_empty_acceptable: true` 를 박고 멈춰라. 더 이상 selector 시도 X. 봇이 등록 후 body_empty_at_baseline=true 면 "본문 추출 안 됨" 경고를 사용자에 자동으로 붙임 — 알림은 제목+URL 만 나가도 OK. content 키는 비워두거나 가장 그럴듯한 후보 한두 개만 두면 됨 (있으면 추가 정보, 없어도 등록 통과).**
- 0건 — row_selector(httpx_html) 또는 list_path(httpx_json) 가 잘못됐다. 위 HTML / list_candidates 를 다시 봐라. SPA 라서 정적 HTML 에 글 목록이 없으면 strategy 를 "playwright_html" 로 바꾸고 list.wait_selector 로 목록이 그려질 때까지 기다려라.
- CSS 선택자 컴파일 실패 / pseudo-class syntax — Tailwind responsive utility class(`md:grid-cols-2`, `xl:px-4`) 를 그대로 class selector 로 복사한 신호다. 먼저 utility chain 을 버리고 `div.grid > article.news-card` 같은 안정 부모 + 행 selector 로 줄여라. 정말 필요할 때만 `.md\:grid-cols-2` 처럼 colon 을 escape 한다.
- **post_id_unique 중복 — row_selector 가 *같은 글의 다중 layout/zone 행* 을 잡고 있다**: (a) CSS class union 의 두 layout (예: `__Wide-*, __Narrow-*` = responsive 데스크탑/모바일 같은 글) → 한 layout 만 (대표는 `__Wide`/`__Item`/`__Card` 류 1순위). (b) hero/sidebar/related zone 재사용 (carousel) → 메인 list 컨테이너 한정 + `row_required_selector` 로 sidebar 제외 (`:has(time)`/`:has(.summary)`). (c) 같은 글이 다른 URL prefix (`/news/<slug>` vs `/news/<slug>/share`) 로 노출 → post_id transform 에 `regex_extract` 로 안정 ID 잘라내거나 row_selector 좁히기. **중복 N건이면 실제 글 수 = total/N 또는 total/2 가 흔함** (responsive 2 layout). 좁힌 selector 가 자체 0건이 되지 않게 위 list_candidates 의 같은 cluster 안 한 layout sample url 로 확인.

수정된 config JSON 하나만 출력하라. 다른 텍스트 없이.
