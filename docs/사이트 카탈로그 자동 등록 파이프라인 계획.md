# 사이트 카탈로그 자동 등록 파이프라인 계획 (rev5, 2026-05-20)

CONTEXT.md 의 **catalog** + **catalog batch run** 어휘. grill-with-docs 세션 11 결정으로 rev4 → rev5 재설계.

## 1. 동기 + 의도

**메인 목표는 `register.py` / probe / 휴리스틱 / prompt 자동화 품질 향상**. 그걸 측정·진단하려면 다양한 사이트 surface 가 N100 (실제 봇 env) 에서 측정되어야 함.

사용자가 Discord 에서 `/preview URL` 매번 치는 걸 자동화 = catalog batch run. 카탈로그 entry 마다 jobs 테이블에 enqueue → bot worker 가 일반 path (`/preview` 와 똑같이) 로 처리. dev 박스에서 register.py 직접 돌리면 IP/네트워크/fingerprint 가 N100 과 달라 진단 가치 X — rev3 의 실수.

rev5 추가: catalog 를 *파일 1개에서 multi-file 로 분리*. 사용자가 한 번에 추가한 chunk 마다 새 파일 → git 편집 가벼움. 분류 의도 X — 의미적으론 1 monotonic pool.

## 2. 모델 (rev5)

- **catalog** = name+url 짝 모음 1개. 파일 1개 (`output/candidates/<name>.yaml`, 파일명 stem = catalog 이름).
- **catalog 의 의미** = 사용자가 한 chunk 로 박은 entry 들의 *편집 편의 partition*. 분류·코호트 X.
- **합집합 = monotonic pool** — 사용자가 아직 안 해본 사이트 후보 전체.
- **cross-catalog dedup 강제** — 같은 url 두 파일에 박이면 driver load 시 fail.
- **이름 가벼움** — `2026-05-20.yaml`, `chunk-2.yaml`, `legacy-2026-05-19.yaml` 식. regex `^[a-z0-9][a-z0-9_-]{0,63}$`.

## 4. 카탈로그 schema (rev5 — multi-file)

위치: `output/candidates/<name>.yaml`. git-ignored 데이터 (rev6 — 위 §1 동기 참조). schema 2 그대로.

```yaml
version: 1
schema: 2
entries:
  - name: 마비노기 (PC) 공지
    url: https://mabinogi.nexon.com/page/news/notice_list.asp
  - name: 메이플스토리 (모바일) 공지
    url: https://m.maplestory.nexon.com/board/7/
```

필드 2개:
- `name` (필수, 문자열, 1~200자) — 사람 읽는 라벨.
- `url` (필수, http(s), ≤1000자).

**dedup**:
- 같은 url 한 catalog 안에 두 번 X (이미 rev4).
- 같은 url **cross-catalog** 두 파일에 X (rev5 신규). driver load 시 다 파일 합치고 검증 — 위반 시 stderr 에 위반 url + 두 파일명 출력 + exit 2.

**이름 자동**:
- dashboard "+ 새 catalog" 시 사용자가 이름 비우면 `auto-YYYY-MM-DD-<seq>.yaml` 자동 (seq = 그 날 ordinal).
- 박았으면 그 이름 검증 (regex) 후 사용.

## 6. Batch driver — `scripts/register_batch.py` (N100 실행)

**위치**: N100 의 `scripts/register_batch.py`. dev 박스에서도 같은 파일 (git tracked) 이지만 *실행은 N100 만*.

**CLI** (rev5):
```
python scripts/register_batch.py
    [--catalog <name>]              # scope: catalog 1개 (파일명 stem) — repeat 허용
    [--url URL]                     # scope: URL 직접 — repeat 허용. catalog 무관.
    [--failed]                      # filter preset: rc ∈ {1, -1, -2, -3, -99}. 마커 자동 clear.
    [--rc <comma-list>]             # filter granular: 예 `--rc=1,-99`. 마커 자동 clear.
    [--force]                       # 마커/jobs 다 무시. 위 filter override.
    [--limit N]                     # enqueue 상한
    [--dry-run]                     # enqueue 안 함, 분포만
```

**scope axis**:
- `--catalog <name>` 1개 이상 (반복) — 명시 파일 합집합. 1개도 박혀야 (default 합집합 X — Q7).
- `--url URL` 1개 이상 (반복) — 직접 URL allowlist. catalog 안 있어도 OK (catalog 없이 URL 만으로 호출 가능).
- 둘 다 박혀도 OK (catalog 의 URL + 명시 URL 합집합).

**filter axis**:
- default = **untried** (jobs row 없는 entry 만).
- `--failed` = preset for retry-worthy: rc ∈ {1, -1, -2, -3, -99} (gen_fail + bug). 해당 slug 의 `.FAILED.json`·`.BUG.json` 마커 자동 삭제.
- `--rc <list>` = granular rc filter. `--rc=1` (gen_fail), `--rc=-99` (worker_exception) 등. 마커 자동 삭제.
- `--force` = 마커/jobs 다 무시. filter override (모든 entry enqueue).

**조합 예**:
- `register_batch.py --catalog=2026-05-20` → 그 catalog 의 untried (기본).
- `register_batch.py --catalog=2026-05-20 --failed` → 그 catalog 의 재시도 가치 실패.
- `register_batch.py --url https://… --url https://…` → 명시 URL 만.
- `register_batch.py --catalog=foo --force` → 다 (조심).

**rc**:
- 0 정상 종료
- 2 catalog load/검증 실패 (cross-catalog dedup 포함)
- 3 catalog 파일 없음
- 4 인자 오류

### 14a. 컴포넌트 지도

| stage | 위치 | 머신 | 역할 |
|---|---|---|---|
| catalog 진본 | `output/candidates/<name>.yaml` | dev box | git-ignored. dashboard / Claude / 손편집 자유 mutate. |
| dashboard 편집 UI | `dashboard/candidates_view.py` (`/candidates`, `/candidates/<name>`) | dev box | bulk paste / inline edit / remove / new — yaml 즉시 atomic replace. |
| sync layer | `scripts/remote.py:_sync_catalogs_to_n100` | dev box → N100 | `--catalog` 들고 `batch-register` 호출 시 *호출 직전* atomic scp (`.tmp.<name>.<pid>.yaml` → `mv`). |
| enqueue driver | `scripts/register_batch.py` | N100 | catalog load + cross-file dedup → `bot.sqlite3` jobs 테이블에 `kind='register', via='batch'` row insert. |
| jobs queue | `bot.sqlite3` jobs 테이블 | N100 | `pending` → `running` → (`done` \| `failed`). `url` PK 로 latest row 가 진실. |
| worker | `bot/worker.py:_process_job_inner` | N100 | `chromium_lock` 잡고 `blocking_register` subprocess 호출. phase ack 갱신, 끝나면 `mark_job_finished`. |
| register subprocess | `scripts/register.py` (via `bot/site_ops.py:blocking_register`) | N100 | probe → recognize → generate. 성공 시 `configs.snapshot/<slug>.json` 박음. 실패 시 marker (`.REJECTED.json` / `.FAILED.json` / `.BUG.json`) 박음. |
| 분포 view | dashboard `/candidates/<name>` | dev box | dev box 의 yaml + N100 의 `bot.sqlite3` snapshot LEFT JOIN on url + `configs.snapshot/<slug>.json` 존재 여부 → status × subkind. |

dev box 가 *읽는* N100 데이터 (`bot.sqlite3`, `configs.snapshot/`) 의 동기 메커니즘은 이 doc 범위 밖 — `dashboard/state.py` 가 별도로 pull (운영 메모 §대시보드).

### 14b. 데이터 흐름 (single entry 추적)

URL u 가 catalog `2026-05-20.yaml` 에 박힌 시점부터:

1. **dev box yaml mutate** — 사용자가 `/candidates/2026-05-20` 에서 bulk paste 또는 손편집. `_save_catalog_doc` 의 `os.replace` 가 atomic.
2. **CLI 트리거** — `python scripts/remote.py batch-register --catalog=2026-05-20` (dev box).
3. **scp** — `_sync_catalogs_to_n100` 가 `output/candidates/2026-05-20.yaml` → N100 의 `.tmp.<pid>.yaml` → `mv` (atomic rename). 실패 시 hard abort (rc=5/6).
4. **SSH 호출** — `ssh n100 'cd ~/notice-watcher && .venv/bin/python scripts/register_batch.py --catalog 2026-05-20 [filter]'`.
5. **driver filter 결정** — u 의 latest jobs row 조회 (`_latest_job_for_url`).
   - filter=untried (default): jobs row 없을 때만 통과.
   - filter=failed: `result_rc ∈ {1,-1,-2,-3,-99}` 일 때 통과 + `STATE_DIR/<slug>.{REJECTED,FAILED,BUG}.json` 삭제.
   - filter=rc=…: 명시 rc 일 때 통과 + 마커 삭제.
   - filter=force: 무조건 통과 + 마커 삭제.
6. **enqueue** — `db.enqueue_job(kind='register', url=u, slug=url_to_slug(u), via='batch', dedupe=True)`. dedupe 가 pending/running 중복 차단 — 같은 url 잡 2개 동시 X.
7. **worker claim** — `bot/worker.py` background task 가 chromium_lock slot 잡고 `_process_job_inner` 진입. `is_registered(slug)` true 면 subprocess 스킵 + `mark_job_finished(ok=True, rc=0, tail='(already registered)')`.
8. **register subprocess** — `blocking_register(url, …)` 가 `scripts/register.py` subprocess 띄움. `[PHASE]` stdout 라인 → ack edit (interactive `/preview` 와 동일 path).
9. **결과 writeback** — `mark_job_finished` 가 jobs row 의 `status`, `result_rc`, `result_tail`, `finished_at` 채움.
   - rc=0 + `is_registered(slug)`: `configs.snapshot/<slug>.json` 존재 → dashboard 가 `status=registered` 로 분류.
   - rc=2 (policy_reject): register 가 이미 `.REJECTED.json` + learned_blacklist.
   - rc=3 (gate_reject): register 가 4 분기 (`nav_only/meta_diverging/multi_host_hub/board_shape`) 중 하나로 `.REJECTED.json` 박음. 빠지면 worker 가 generic fallback.
   - rc=1 (gen_fail): `.FAILED.json` 박힘. triage 큐 append.
   - rc=-1/-2/-3 (chromium_lock timeout / subprocess timeout / 예외): `.BUG.json` 박힘. fast-skip.
10. **dashboard 갱신** — 다음 `/candidates/<name>` GET 시 `_classify` 가 그 slug 의 jobs row + `configs.snapshot` 보고 status 결정. KPI / 분포 / 행별 표시 갱신.

### 14c. CLI 시나리오 3 종

**A. 새 catalog 첫 batch run**:
```
# dev box
python scripts/remote.py batch-register --catalog=2026-05-20
```
→ N100 scp + untried entry 만 enqueue. drain 까지 worker 가 chromium_lock slot 만큼 병렬 처리.

**B. 자동 등록 실패 retry (gen_fail + bug)**:
```
python scripts/remote.py batch-register --catalog=2026-05-20 --failed
```
→ `rc ∈ {1,-1,-2,-3,-99}` 인 url 의 marker (.FAILED / .BUG) 자동 삭제 + 재 enqueue. policy_reject (rc=2) / gate_reject (rc=3) 는 *제외* — 정책 거부는 retry 무의미.

**C. 특정 rc 만 retry (granular)**:
```
python scripts/remote.py batch-register --catalog=2026-05-20 --rc=1,-99
```
→ `result_rc ∈ {1, -99}` 인 url 만.

**D. 명시 URL 한 줌만 (catalog 무관)**:
```
python scripts/remote.py batch-register --url https://… --url https://…
```
→ scp 단계 스킵 (catalog 없음). URL 만으로 enqueue. catalog 안 있어도 OK — host 가 자동 name.

**E. 강제 재시도 (조심)**:
```
python scripts/remote.py batch-register --catalog=… --force
```
→ jobs row / marker 다 무시. 모든 entry enqueue. policy_reject 도 다시 침. 정책 거부 사이트도 재침입.

### 14d. 진단 — 어디 보고 어디 조회

- **per-catalog 진행률 + 분포**: dashboard `/candidates/<name>`. KPI bar + status × subkind 분포 표 + 행별 표.
- **per-row 상세**: 행 클릭 → slug 링크 → `/sites/<slug>` (각 사이트 detail).
- **job tail 보기**: dashboard `/jobs/<id>` 또는 N100 sqlite query.
- **trace 보기**: `python scripts/remote.py trace-index probe` / `trace-fetch <trace_id>`.
- **catalog 합집합 위반 (cross-file dup)**: driver load 시 `rc=2` 로 abort. stderr 에 첫 발견 catalog + 충돌 catalog 두 이름 출력.

### 14e. 실패 경로 / 자가-치유

- **scp 실패**: `_sync_catalogs_to_n100` 가 hard abort (rc=5 or 6). stale yaml 로 진행 X. 사용자는 SSH/네트워크 점검 후 재호출.
- **N100 동시 mutate 없음**: dev box → N100 단방향. N100 직접 `output/candidates/` 편집 금지 (CLAUDE.md §5 rule B 예외).
- **`bot.sqlite3` 충돌**: driver 가 `db.enqueue_job(dedupe=True)` — 같은 url 의 pending/running row 있으면 새 row 안 박고 그 id 반환 ("dup" 라벨).
- **worker 죽음**: jobs row `status='running'` 인 채 봇 재시작 시 다음 polling 에서 `attempts ≥ 1` 감지 + `.BUG.json` 박고 fast-skip.
- **catalog yaml 손상**: `_load_one_catalog` 가 schema/필드 검증 → rc=2 abort. dashboard 의 `_load_catalog_doc` 는 silent return None (UI 안 깨짐).

### 14f. 한계 / 미해결

- catalog 의 *N100 진본 부재* 가 의도 — dev box 가 단일 진본. 다중 operator (여러 사람이 dev box 동시 편집) 시 yaml race 가능. 단일 owner 가정.
- `--failed` preset rc 집합 (`{1,-1,-2,-3,-99}`) 은 register subprocess + worker 가 박는 rc 와 결합 — fail taxonomy 확장 시 동기화 필요.
- dashboard 는 trigger 안 함 (rev5 정책). Claude/CLI 만 호출. 비기술 사용자 트리거 원하면 별도 ADR.

## rev6 — catalog 데이터화 (2026-05-20 저녁)

### 동기

rev5 의 `output/candidates/<name>.yaml` git-tracked 모델에서 발견된 결함:
- dashboard 의 ✏ inline edit / bulk add / 행별 🗑 가 dev box 의 yaml 만 갱신.
- N100 은 git pull 받기 전까지 *옛 committed* yaml 만 봄.
- `remote.py batch-register --catalog=foo` 호출 시 N100 옛 yaml 기준으로 enqueue → dashboard 에서 박은 새 URL 영영 안 잡힘.

CLAUDE.md §1 "코드 변경 = dev box only via git" 의 *코드* 적용 범위 밖. catalog yaml = *데이터* (URL list 자주 mutate, 누가 봐도 mutable runtime state). git 으로 commit/push/pull cadence 강요는 카탈로그 편집 부담 ↑ 가치 ↓.

### 결정

catalog yaml 위치를 `configs/candidates/` (git-tracked) → `output/candidates/` (git-ignored 데이터) 로 이동.

- dev box 가 **유일한 진본** (dashboard 가 쓰는 곳).
- N100 동기는 `scripts/remote.py batch-register` 호출 시점에 **atomic scp** 1회.
- per-edit commit/push 없음 — 사용자가 dashboard 에서 자유롭게 URL 추가/편집/삭제. 다음 batch run 시점에 자동 동기.

### CLAUDE.md §5 rule B 예외 명시

기존 rule B: "N100 직접 작성 가능 = output/ 뿐". rev6 가 만드는 새 카테고리:

**output/candidates/** = *shared operational input* — dev box 가 쓰고 N100 이 읽는 자리. 다른 output/ 항목 (poll_state/, traces/, probe/, bot.sqlite3 등) 은 N100 이 쓰는 runtime data 와 반대 방향. dev box → N100 단방향 scp 만 일어남, N100 직접 쓰기 X.

### 구현

- `scripts/register_batch.py:CATALOG_DIR` = `ROOT/output/candidates`.
- `dashboard/candidates_view.py:CATALOG_DIR` = `ROOT/output/candidates`.
- `scripts/remote.py:cmd_batch_register` 의 `--catalog` 인자가 있으면 호출 전 `_sync_catalogs_to_n100(catalogs)`:
  1. `_CATALOG_NAME_ARG_RE` 정규식 통과 검증.
  2. dev box 의 `output/candidates/<name>.yaml` 존재 확인 — 없으면 abort (rc=5).
  3. SSH `mkdir -p ~/notice-watcher/output/candidates` (idempotent).
  4. scp local → N100 `output/candidates/.tmp.<name>.<pid>.yaml`.
  5. SSH `mv` → `output/candidates/<name>.yaml` (atomic rename).
  6. 각 step 실패 시 hard abort + temp 청소 시도 (rc=6).
- 마이그: `cp configs/candidates/*.yaml output/candidates/` + `git rm configs/candidates/*.yaml`. git log 에 옛 위치 history 보존.

### codex 검토 결과 (이 plan 의)

A. CLAUDE.md §1~5 일관. rule B 의 *shared operational input* 예외 명시 필요 (이 문서 §rev6 가 그것).
B. scp 인자 안전: `_CATALOG_NAME_ARG_RE` regex 가 path traversal / shell metachar 차단.
C. dev box concurrent edit race — 단일 owner 운영 가정 하 저-위험. 다중 operator 시 per-catalog lock 필요.
D. scp 실패 시 hard abort 강제 (silent stale-run 방지) + atomic temp+mv (partial-read race 차단). 둘 다 구현됨.
E. 마이그 window: `git rm configs/candidates/` commit → N100 pull 후 첫 batch run scp 전까지 catalog 없음. 영향 X (dashboard = dev box only, N100 catalog 사용은 batch run 만).
F. atomic copy 의 대안 (rsync, bind-mount) 폐기 — scp + remote mv 가 가장 simple.
G. plan 가치: per-edit commit/push 부담 제거 + 사용자 의도 단순화. dashboard live-edit 의 핵심 가치 달성.
