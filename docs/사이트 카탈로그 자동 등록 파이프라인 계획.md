## 5. Batch driver — `scripts/register_batch.py` (N100 실행)

**위치**: N100 의 `scripts/register_batch.py`. dev 박스에서도 같은 파일 (git tracked) 이지만 *실행은 N100 만*. dev 박스 실행 X.

**CLI**:
```
python scripts/register_batch.py [--limit=N] [--force] [--dry-run]
```

**흐름** (N100 에서 호출됨):
1. catalog.yaml load + 검증 (name/url 필드 + dedup).
2. 각 entry url 마다 jobs 테이블 검사:
   - 기본: `SELECT 1 FROM jobs WHERE url=?` row 있으면 skip (untried-only, Q8).
   - `--force`: skip 안 함. + 같은 slug 의 `.REJECTED/.FAILED/.BUG.json` 마커 삭제 후 진행 (Q10B).
3. `bot.db.enqueue_job(kind="register", url=url, slug=url_to_slug(url), via="batch", ack_channel_id=None, ack_message_id=None, sub_payload=None, requested_by=None, dedupe=True)`.
4. dedupe=True → 같은 (kind, slug) 가 pending/running 이면 새 enqueue 안 함 (기존 db.enqueue_job 동작).
5. enqueue 시점에 가드 안 거침 — worker 의 claim 시점 가드 (`is_rejected` / `is_registered` / `_gate_check`) 가 결정.
6. driver 가 enqueue 한 cand 수 + skip 수 출력. ack 없음.

**Worker 처리** (변경 X):
- `kind='register' AND ack_channel_id IS NULL` 이면 ack edit 자연 skip (re-probe 패턴, 이미 코드 박혀있음).
- 일반 path: `claim` → 가드 → `subprocess.run('register.py URL')` → rc 분기 → jobs row 갱신 + 마커 박음.
- OWNER DM 안 보냄 (Q6).

**구분**: jobs 테이블에서 `via='batch'` = catalog batch 출신. `/jobs` 페이지 / `/candidates` 페이지 거기서 필터.

## 6. Dashboard `/candidates`

좌측 nav 그대로. 페이지 구성:

1. **요약 KPI** (status × fail_kind/fail_subkind 분포):
   - registered (rc=0)
   - gen_fail (`.FAILED.json`, rc=1) × subkind (`posts_nonempty`, `article_body_len`, `published_at_iso`, ...)
   - policy_reject (rc=2)
   - gate_reject (rc=3) × subkind (`recognizer:<name>`, `nav_only`, `board_shape`, `multi_host_hub`, ...)
   - bug (rc=-1/-2/-3/-99) × subkind
   - untried (jobs 테이블에 row 없음)

2. **상세 표** — 행별: name / url / status / fail_subkind / slug → `/subs/<slug>` (등록됨) or `/jobs?slug=<slug>` (그 외).

3. **액션**:
   - 행 별 🗑 — catalog.yaml 에서 entry 제거.
   - "+ 새 entry 추가" — name + url 박음.
   - **"▶ batch run"** 버튼 — POST `/candidates/batch-run`. dev 박스 `scripts/remote.py batch-register` 호출 (SSH). `--force` 토글 옵션.

**데이터 source**: catalog.yaml ↔ N100 snapshot 의 `bot.sqlite3` jobs 테이블 (LEFT JOIN url 키). 별도 sqlite (`output/register_batch_runs.sqlite3`) 폐기.

## 11. ADR 후보

이 결정 중 hard-to-reverse + surprising + real-trade-off 한 것:

- **catalog batch 가 별도 sqlite 가 아닌 `bot.sqlite3` jobs 테이블 재사용** — 대안 (별도 sqlite) 폐기. 이유: 분류 인프라 (fail_kind/fail_subkind) 일관, snapshot pull 단순. 미래 schema 진화에 영향.
- **via='batch' 새 enum 값** — `preview`/`watch`/`poll-reprobe` 와 같은 layer. CHECK constraint 없어 마이그 X, 코드만 인지.

별도 ADR 박을지 사용자 결정 (skill 가이드: 셋 다 충족 시만).
