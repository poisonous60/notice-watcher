# notice-watcher 봇 명령어

봇 사용자가 칠 수 있는 모든 슬래시 명령. 응답은 전부 **ephemeral**(본인만 보임). 알림 발송 자체는 폴링 직후 즉시(`schedule='realtime'`).

> 빠른 안내: 봇 안에서 `/help` 치면 핵심 명령이 embed 로 뜸.

---

## 일반 사용자

### `/watch`

게시판 URL 을 등록해 새 글 알림을 받음.

| 인자 | 필수 | 설명 |
|---|---|---|
| `url` | ✓ | 공지/게시판 목록 페이지 URL (`https://` 시작) |
| `filter` | | 자연어 필터. 예: `"점검 공지는 빼고 신규 콘텐츠/이벤트만"`. 비우면 새 글 전부 받음 |
| `here` | | 켜면 이 채널에 발송, 끄면(기본) 내 DM |
| `notify_empty` | | 켜면(기본) 새 글 없을 때도 "새 공지 없음" 한 줄 받음. 끄면 새 글 있을 때만 |
| `article_url` | | 자동 분석 실패할 때 그 게시판의 실제 글 하나 URL — 분석 성공률↑ |

이미 등록된 사이트면 즉시 구독 추가 + 예시 알림. 신규 사이트는 jobs 큐에 enqueue → worker 가 처리 후 메시지 edit.

### `/list`

내 구독 목록을 Discord **Components V2** UI 로 표시. 각 행은 `[<display_title>](<url>)` 클릭으로 외부 URL 이동 + 행 옆 ❌ 버튼으로 즉시 해제.

페이지당 **8개** (Components V2 의 40 children 한계 — Section=4 children 카운트), 9개 이상이면 `[◀ 이전][다음 ▶]` 페이지 nav 자동.

- `display_title` 은 등록 시 register.py 가 board URL HTML `<title>` 추출해 박음. NULL 또는 짧음/generic(Blog/Home 등) 이면 URL host+path fallback.
- **필터 수정 기능 없음** (Discord Modal UX 거부 + inline text edit 미지원). 필터 바꾸려면 `/watch <url> filter:...` 재호출 (upsert 동작).
- View timeout 300s — 5분 후 버튼 dead, 사용자 재 `/list`.

### `/setting`

공지 수신 여부와 매일 발송 시각을 버튼 + Modal UI 로 설정.

- DM: 공지 ON/OFF, 발송 시각(HH:MM)
- 서버 채널: `Manage Channels` 권한이 있으면 채널 공지 ON/OFF, 채널 발송 시각(HH:MM)
- DM 에서 호출하면 채널 버튼은 표시하지 않음

### `/report`

구독 문제 신고 또는 URL 기반 지원 요청. 관리자가 `inspector` 자동 진단 + 수동 조치.

| 인자 | 필수 | 설명 |
|---|---|---|
| `issue` | ✓ | 자연어 문제 설명 (예: `"공식 탭 글만 받고 싶은데 일반 게시판이 와요"`) |
| `slug` | | 문제 있는 본인 구독 slug (자동완성) |
| `url` | | 문제 있는 URL 또는 지원 요청 URL (`https://`) |

`slug` 또는 `url` 중 하나는 필요. 둘 다 있으면 `slug` 기준으로 진단하고 URL 은 부가 정보로 저장.
URL 없는 자유 의견은 `/feedback` 으로 보냄.

### `/feedback`

자유 의견. slug 무관 (구독과 연관 없어도 됨).

| 인자 | 필수 | 설명 |
|---|---|---|
| `message` | ✓ | 의견 본문 (자연어, 기본 **최대 5700자**, `.env` `FEEDBACK_MAX_LEN` 으로 조정) |

`feedback` 테이블에 저장 + OWNER DM 으로 즉시 전달. status/triage 없음 — owner 가 읽기만.

길이 한계는 `bot/config.py::feedback_max_len()` 이 읽음. `.env` 에 `FEEDBACK_MAX_LEN=4000` 같이 두면 즉시 반영(slash 명령은 매 호출마다 다시 읽음). discord STRING 인자 한계 6000 안쪽으로 유지.

### `/status`

봇·폴링 상태. 가동시간, URL 게이트 거부 통계, 잡 큐 카운트, 마지막 폴링 시각, 깨짐 신호 있는 slug, 자동 등록 실패 slug, 마지막 에러.

### `/help`

명령어 요약 embed. 평문 빠른 참조.

## Owner / 관리자 — `/admin …` (ADMIN_GUILD_ID 길드에서만)

`ADMIN_GUILD_ID` env 가 가리키는 private guild 에만 등록 → 다른 길드/DM 의 autocomplete 에 노출되지 않음. 사용자 확인은 `str(interaction.user.id) == OWNER_USER_ID` 일치만 봄. 결과는 호출 채널엔 ephemeral ack 만, 실제 dump 는 OWNER DM 으로.

### `/admin recent`

최근 register 잡 N개 (등록 흐름 추적).

| 인자 | 기본 | 범위 |
|---|---|---|
| `count` | 20 | 1–50 |

### `/admin triage`

처리 대기 backlog 요약. 카운트: 미해결 신고(open), 깨짐 신호 slug, 자동등록 실패 slug, 잡 큐 pending/running, 의견 누적/최근 7d.

인자 없음. 결과는 OWNER DM 으로.

### `/admin reports`

사용자 신고 목록.

| 인자 | 기본 | 값 |
|---|---|---|
| `status` | `open` | `open` / `resolved` / `all` |

### `/admin feedback`

`/feedback` 으로 받은 자유 의견 목록 (최근 N건).

| 인자 | 기본 | 범위 |
|---|---|---|
| `count` | 10 | 1–50 |

### `/admin preview`

등록 없이 그 게시판 최신 글 한 건을 요약해 알림 예시 표시. 일반 사용자 명령에서는 숨기고 admin guild 하위 명령으로만 노출.

| 인자 | 필수 | 설명 |
|---|---|---|
| `url` | ✓ | 게시판 URL |
| `article_url` | | 자동 분석 실패 대비 실제 글 URL |

### `/admin inspect`

구독·잡·config·state 통합 dump + 자동 진단. `job_id` / `report_id` / `user_id` / `slug` 중 하나 이상.

### `/admin fetch`

현 config 로 `fetch_list` 돌려 top N 결과 + 진단 갱신.

| 인자 | 기본 |
|---|---|
| `slug` (필수) | — |
| `count` | 5 (1–20) |

### `/admin resolve`

신고를 해결로 표시.

| 인자 | 필수 | 설명 |
|---|---|---|
| `report_id` | ✓ | reports.id |
| `note` | | 해결 메모 |

### `/admin announce`

봇 공지 발송. preview 표시 후 버튼 `[발송]`/`[취소]` 으로 확정. 발송 시 옵트인 DM + 옵트인 채널 양쪽으로.

| 인자 | 필수 | 설명 |
|---|---|---|
| `message` | ✓ | 본문 (markdown 허용, ~4000자) |
| `title` | | 제목 (기본 `📢 봇 업데이트`, 최대 256자) |

발송 결과는 OWNER DM 으로 (성공/실패 카운트 + 실패 상세 최대 20건). `announcements` 테이블에 audit row.

## 발송 정책 요약

- **알림** (`/watch` 등록 결과): 폴링 직후 즉시. `scripts/notify.py` 가 봇 토큰으로 REST 직접 호출 — 봇 프로세스 안 떠있어도 발송 가능.
- **공지** (`/admin announce`): owner 가 발송 시점에 봇 게이트웨이로 직접 sendd. SEND_SLEEP=0.5s/타깃, 실패는 회차 skip 후 다음 공지 재시도(자동 옵트아웃 없음).

## 옵트아웃 의미

`announce_prefs(scope_kind, scope_id, opted_out)` — 기본 opt-in (행 없음 = 수신). 옵트아웃 시 `opted_out=1` 행 생성/갱신.

- DM 옵트아웃: 그 user 한테 공지 안 보냄. 일반 알림(`/watch` 등록한 글) 은 영향 없음.
- 채널 옵트아웃: 그 채널에 공지 안 보냄. 일반 알림은 영향 없음.

## 보안

- `/admin …` 명령은 ADMIN_GUILD_ID + OWNER_USER_ID 둘 다 일치해야 동작 (둘 중 하나라도 안 맞으면 ephemeral 거부 + 길드 autocomplete 비노출).
- 공지 confirm view 는 호출한 owner 만 버튼 클릭 가능 (`interaction_check`).
- 봇 토큰·OWNER_USER_ID 는 운영자 `.env` 에서 주입.
