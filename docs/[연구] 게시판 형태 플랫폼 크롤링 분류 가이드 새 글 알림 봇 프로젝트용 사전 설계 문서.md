# 게시판 형태 플랫폼 크롤링 분류 가이드: "새 글 알림 봇" 프로젝트용 사전 설계 문서

## TL;DR

- **결론: 한 가지 접근법으로는 안 된다.** 사이트는 (1) RSS/공식 API가 있는 곳, (2) JSON XHR을 엿보기만 하면 되는 SPA, (3) 정적 HTML 파싱, (4) Cloudflare/Akamai/CAPTCHA에 막혀 헤드리스 브라우저나 우회가 필요한 곳 — 4개 계층으로 갈린다. 봇은 **사이트별 어댑터(adapter) 패턴**으로 설계하고, 우선순위는 RSS → 공식 API → 비공식 JSON → HTML → 헤드리스 순.
- **한국 게임사 중 공지사항을 진짜 공개 API로 제공하는 곳은 사실상 스마일게이트 로스트아크 한 곳뿐**(`developer-lostark.game.onstove.com /news/notices`, JWT 인증). 나머지(넥슨·NC·크래프톤·펄어비스)는 HTML 폴링 또는 비공식 JSON이 필수이며, 디시인사이드·아카라이브·네이버 카페는 봇 차단 강도가 매우 높아 별도 우회 전략이 필요하다.
- **시작 권장 순서:** Steam(`api.steampowered.com/ISteamNews` + 게임별 RSS), Discourse 기반 포럼(`/latest.json`), Reddit (`.rss`), 루리웹 RSS, 로스트아크 Open API → 그다음 HTML 폴링(인벤, BDO, 마비노기, MapleStory 모바일) → 마지막에 SPA·Cloudflare 사이트(에픽세븐, 아카라이브, 디시인사이드, 네이버 카페). Twitter/X와 네이버 카페는 비용·ToS 측면에서 가능하면 봇 범위 제외 권장.

---

## Key Findings

1. **학술 분류 체계가 이미 존재.** Bhardwaj 외(2026) arXiv 2601.06301 *Beyond BeautifulSoup* 는 35개 사이트를 5단계 난이도(Simple HTML / Complex HTML / Simple Auth / Complex Auth / CAPTCHA)로 분류했고, USENIX Security '24 Stafeev & Pellegrino *SoK: State of the Krawlers* 는 2010~2022년 보안·웹 측정 논문 1,057편을 라벨링하여 크롤러 알고리즘을 빌딩블록 단위로 분해했다. 두 논문 모두 "사이트 구조(static vs dynamic vs auth-gated)"가 1차 분류축, "anti-bot 보호 강도"가 2차 분류축임을 시사한다. **이 5-tier 라벨을 봇 사이트 등록 메타데이터로 그대로 차용 가능.**
2. **공식 API/RSS가 있는데 의외로 모르고 헤드리스로 긁는 경우가 많다.** Steam의 `ISteamNews/GetNewsForApp` JSON API 와 게임별 `store.steampowered.com/feeds/news/app/{appid}` Atom 피드, Discourse의 `.json` 엔드포인트(모든 페이지 URL에 `.json`을 붙이면 JSON 응답), Reddit의 `reddit.com/r/{name}/.rss`, MediaWiki 공식 API — 이 4개 카테고리만 잘 활용해도 글로벌 게임/포럼 공지의 상당 부분을 일반 도구로 처리할 수 있다.
3. **2023~2026년 사이 "공식 API"는 사실상 죽었거나 폭등했다.** Twitter/X는 무료 티어 폐지 후 Basic $100/월로 시작했다가 2025년 1월 $200/월로 인상됐고, 2026년 2월 6일부터 신규 개발자에게는 종량제(pay-per-use, 약 $0.01/post 생성·$0.005/post 읽기)가 기본 적용되며 Legacy Basic($200)·Pro($5,000)은 기존 구독자 전용으로만 유지된다. Enterprise는 **월** $42,000~$50,000 수준(연 $500K+). Reddit은 2023년 7월 1일부터 제3자 앱 개발자에게 1,000 API 호출당 $0.24 부과를 시작했다(Apollo 추산 연 $20M). 일반 개발자 봇은 **공식 API에 의존하면 비용이 가파르게 오르므로 RSS·웹 인터페이스 폴링·서드파티 미러로 fallback 설계가 필수**.
4. **한국 시장의 봇 차단 분포가 글로벌과 다르다.** 아카라이브는 Cloudflare + 자체 캡차/IP 차단을 운영(공식 공지로 "비정상 스크래핑은 이용 제한" 명시), 디시인사이드는 클라우드 IP 자체를 거의 차단하며 **모바일 사이트(`m.dcinside.com`)를 사실상 API처럼 쓰는 게 관행**, 네이버 카페는 로그인+iframe+캡차 3중 장벽으로 가장 어렵다.
5. **"플랫폼 종류" 분류보다 "기술 스택 fingerprint" 인식이 ROI가 높다.** 같은 Discourse 엔진을 쓰는 사이트(Blizzard US Forums, Meta Discourse, FastAPI 커뮤니티 등)는 한 어댑터로 N개 사이트 처리 가능. 같은 vBulletin은 `showthread.php/forumdisplay.php` URL 패턴, phpBB는 `viewforum.php/viewtopic.php`로 식별 가능. **분류 시 엔진 fingerprint를 1차 기준, 봇 차단 수준을 2차 기준으로 두는 것이 코드 재사용 측면에서 가장 좋다.**

## Details

### 1) 기술 구조 분류 (Rendering / Transport 축)

| 유형 | 식별 단서 | 대표 사이트 | 권장 접근법 | 난이도 |
|---|---|---|---|---|
| **A. 정적 HTML (server-rendered)** | View-source에 제목 다 보임. `.asp`/`.php`/`.html` URL | 마비노기 공지, BDO 공지, 인벤, 루리웹, 클리앙, Wikipedia, Daum PUBG BBS | `requests` + `BeautifulSoup`/`lxml`. ETag/Last-Modified 활용 | ★☆☆☆☆ |
| **B. 서버 렌더 + 부분 hydration** | 첫 HTML에 데이터 있지만 일부 위젯은 JS로 채워짐 | MapleStory, DNF, FC Online, Lost Ark 공식 홈, Steam Store 뉴스 페이지 | `requests` 우선; 안 보이면 모바일 도메인(`m.*`) 시도 | ★★☆☆☆ |
| **C. SPA + JSON XHR (백킹 API 노출)** | View-source에 데이터 없음. DevTools Network에서 `/api/...` JSON 발견 | NC plaync 계열(Aion2, TL, 리니지W), Epic Seven (`api.onstove.com`), HoYoLAB (`bbs-api-os.hoyolab.com`), PUBG.com 글로벌 | **헤드리스 쓰지 말고 JSON 엔드포인트 직접 호출.** UA/Referer 헤더만 맞추면 됨 | ★★☆☆☆ |
| **D. SPA + 인증 토큰/CSRF 필수** | JSON 응답에 `401`/`403` 또는 `_csrf` 쿠키 요구 | Naver Cafe (로그인 세션), Discord 채널 (Bot Token 필수), Reddit OAuth | OAuth/API 키 또는 로그인 세션 캐싱 | ★★★☆☆ |
| **E. Heavy SPA + 봇 보호** | TLS/JA4 fingerprint 검사, Turnstile, 행동 분석 | 아카라이브(arca.live), 일부 Cloudflare Pro 사이트 | `cloudscraper` → `curl-impersonate` → Playwright stealth (단계적). 최후에 Scrapfly/ZenRows 같은 상용 우회 API | ★★★★☆ |
| **F. iframe-in-iframe / 임베디드 위젯** | 게시판이 별도 도메인 iframe에 들어감 | 네이버 카페(`cafe_main` iframe), 일부 학교 공지 | iframe URL 직접 추출 후 그 안을 A 또는 C로 처리 | ★★★☆☆ |
| **G. CAPTCHA-gated** | reCAPTCHA v2/v3, Turnstile, Geetest 강제 | DCinside 비정상 트래픽 감지 후, 로그인 화면 | 정상 사용자 흉내 + rate 제한 + 모바일 도메인 우회. 마지막 수단은 2Captcha/CapSolver 같은 외주 캡차 서비스 | ★★★★★ |

**arXiv 2601.06301의 5-tier 매핑**: Simple HTML(A) → Complex HTML(B) → Simple Auth(D 일부) → Complex Auth(D + MFA) → CAPTCHA(G). 동 논문 Table 2의 **추출 성공률(Extraction Success Rate, 3회 평균)**은 다음과 같다: BeautifulSoup는 Simple HTML 0.93, Complex HTML 0.80이지만 Auth부터 "Not Supported"; Scrapy는 0.82/0.20/Not Supported; Claude(agent)는 1.00/0.57/0.20/0.12/0.05; Simular.ai(visual agent)는 1.00/1.00/0.63/0.70/0.10. 즉 **정적/단순 사이트엔 전통 도구가 압도적으로 빠르고(실행시간 <2초 vs 10~20초), 인증/캡차 필요 사이트엔 LLM 에이전트만 그나마 동작**한다. 알림 봇 관점에서는 인증 필요 사이트는 가능하면 제외하거나 ID/PW 등록 + 세션 캐싱이 현실적.

### 3) 콘텐츠 유형 분류 (Transport 축, 우선순위 순)

```
[1순위] 공식 RSS/Atom  ─── Steam(게임별), Ruliweb, Nintendo(일부 국가), Reddit(.rss),
                          대부분 뉴스 사이트
                          → 가장 안정적, 폴링 간격 5~15분, ETag 사용
                          
[2순위] 공식 REST/JSON ─── Steam ISteamNews, Lost Ark Open API, Discourse */.json,
                          Reddit OAuth API(무료 100 QPM), MediaWiki, Discord Bot API
                          → 인증 필요할 수 있으나 스키마 안정적
                          
[3순위] 비공식 JSON ───── HoYoLAB bbs-api-os, NC api.plaync.com, Stove api.onstove.com,
                          DCinside 모바일 사이트(사실상 JSON-ish)
                          → DevTools Network로 발견. 스키마 깨질 위험 ★★★
                          
[4순위] HTML 스크래핑 ─── 마비노기 공지(.asp), BDO, MapleStory(모바일), 인벤,
                          Naver Cafe(로그인 후), 아카라이브
                          → BeautifulSoup/cheerio. selector 변경시 매주~매월 깨짐
                          
[5순위] 헤드리스 브라우저 ─ 위 4단계 모두 막힌 Heavy SPA / 캡차 사이트
                          → Playwright + stealth + 주거용 프록시. 비용·유지보수 ★★★★★
```

**공식 RSS를 확실히 제공하는 주요 플랫폼** (2026년 5월 기준):
- Steam (게임별): `store.steampowered.com/feeds/news/app/{appid}/?cc=US&l=english`
- Steam (통합): `store.steampowered.com/feeds/news.xml`, `feeds/daily_deals.xml`
- Steam Community 그룹: `steamcommunity.com/groups/{name}/rss/`
- Reddit (모든 공개 서브레딧): `reddit.com/r/{name}/.rss`, `.../new.rss`
- 루리웹: `bbs.ruliweb.com/news/board/{id}/rss`, `bbs.ruliweb.com/game/{id}/board/rss`
- Nintendo Europe: 공식 RSS 제공 (Nintendo UK 지원 페이지 참조)
- Nintendo 팬사이트 RSS는 풍부: GoNintendo `gonintendo.com/feeds/all.xml`, NintendoEverything, Nintendo Life `nintendolife.com/feeds/latest`
- Epic Games **Store/뉴스 공식 RSS는 미제공**, statuspage.io Atom만 존재. LootScraper(`github.com/eikowagenknecht/lootscraper`)가 비공식 미러
- Blizzard 공식 RSS는 **다년간 요청에도 미제공**. 팬 사이트 RSS(Blizzard Watch `blizzardwatch.com/feed`)로 대체

**공식 API가 있는 플랫폼**:
- Reddit (2023년 7월 유료 전환, 무료 OAuth 100 req/min 비상업적 한정)
- Discord (Bot Token 무료)
- Steam Web API (무료, key 발급)
- **Lost Ark (무료, JWT) — 한국 게임사 중 유일한 공식 공지 API**
- PUBG (`developer.pubg.com`, 10 req/min, 단 공지 엔드포인트 없음)
- Twitter/X (Basic $200/월부터, 2026년 2월 6일 이후 신규 개발자엔 pay-per-use)
- Naver Open API (자기 카페 글쓰기·검색만, 타 카페 읽기 불가)
- MediaWiki/Wikipedia (무료, anonymous OK)
- Discourse (사이트별 API key 또는 `.json` 접미사로 무인증 read)

**RSS도 API도 없이 HTML만 가능한 군**:
- 인벤, 클리앙(공식 폐지), 아카라이브, 디시인사이드, 한국 게임사 공지 대부분(로스트아크 제외), 네이버 카페, Naver Blog 일부, Heavy SPA로 전환된 일부 글로벌 게임사 뉴스 페이지(Riot, Blizzard)

### 4) 기존 분류·벤치마크 자료 (학술·커뮤니티)

- **arXiv 2601.06301 *Beyond BeautifulSoup* (Bhardwaj, Diwan, Wang, AAAI 2026 사전출판본, 2026년 1월)**: 35개 사이트 5-tier 분류 + LLM-assisted Scripting(LAS) vs End-to-End LLM Agent(ELA) 워크플로 비교. Table 1의 카테고리별 대표 사이트가 명시되어 있다 — Simple HTML: The Hacker News, Wikipedia, Investopedia, Goodreads; Complex HTML: CNN, BBC, NYT, Reuters, National Geographic, NPR, Vimeo; Simple Auth: PayPal, eBay, edX, Coursera, Figma, YouTube, Netflix, Apple, Spotify, GitHub; Complex Auth: Facebook, Reddit, Microsoft, Ticketmaster, Booking.com, Macy's, Bitly, Amazon, Slack, Expedia; CAPTCHA: reCAPTCHA v2/v3 demos, 2Captcha demos, Geetest demo. **이 라벨 체계를 봇 사이트 등록 시 메타데이터로 그대로 차용 가능.**
- **USENIX Security '24 *SoK: State of the Krawlers*** (Stafeev, Pellegrino, CISPA): 2010~2022년 보안·웹 측정 분야 1,057개 논문을 라벨링하여 크롤링 알고리즘(BFS, DFS, randomized 등)을 빌딩블록 단위로 분해. Arachnarium 프레임워크로 9개 실제 + 2개 벤치마크 앱 + Top 10K CrUX 사이트에서 code/link/JavaScript source coverage를 측정. 결과: **randomized 알고리즘이 BFS/DFS보다 커버리지가 좋다.** 본 봇 프로젝트는 "최신 N개 글" 폴링이라 깊이 탐색 알고리즘은 불필요하지만, 카테고리 분류 부분이 참고가 됨.
- **arXiv 2602.15189 *ScrapeGraphAI-100k***: 100K 사이트 스키마 다양성·실패 모드 카탈로그. LLM 기반 정보 추출 벤치마크.
- **상용·블로그 분류표**: Scrapfly의 anti-bot 등급표(Cloudflare/Akamai/DataDome/PerimeterX 비교, JA3/JA4 fingerprint), ZenRows의 "9 best methods to bypass Cloudflare", Bright Data의 static vs dynamic 가이드, ScraperAPI의 Akamai/PerimeterX 우회 가이드. 학술 자료보다 실무 분류표로 더 유용.
- **봇 개발용 레퍼런스 GitHub 프로젝트**: `krepe90/user-hotdeal-bot`(한국 핫딜 사이트 통합 폴링, 모듈식 Crawler 클래스 + Telegram + JSON state 영속화 — 이 봇 프로젝트의 가장 좋은 아키텍처 템플릿), `eikowagenknecht/lootscraper`(Steam/Epic/Amazon/GOG 무료 게임 알림, Discord/Telegram/RSS 출력), `eunchuldev/dcinside-python3-api`(DC 비공식 async wrapper), `Memilmook/dcinside-API-with_Python3`(DC 모바일 엔드포인트 활용), `IsotropicUniverse/NaverCafe-noti`(네이버 카페 새 글 텔레그램 알림 봇).

## Recommendations

### Stage 1 (1~2주, 즉시 착수)
1. **공식 RSS/API만 쓰는 사이트 10~15개로 MVP**. 후보: Steam ISteamNews API(원하는 appid 리스트만), 루리웹 게임별 RSS, Lost Ark Open API, Reddit `.rss`, Discord Bot(자체 서버), Discourse `/latest.json` 패턴(Blizzard US Forum 등).
2. 사이트별 어댑터 추상 인터페이스 작성. **권장 템플릿**: `github.com/krepe90/user-hotdeal-bot`(Python 3.11, aiohttp + BeautifulSoup + Telegram, modular Crawler 클래스, JSON state 영속화, 도커화). 게임 분야의 유사 사례는 `eikowagenknecht/lootscraper`.
3. 상태 저장: 마지막으로 본 글 ID/타임스탬프를 SQLite 또는 JSON으로. ETag/`If-Modified-Since` 활용해 무의미한 traffic 최소화.

### Stage 2 (3~4주, HTML/비공식 JSON 추가)
4. **정적 HTML 한국 게임사 공지 추가**: 마비노기, BDO, FC Online, MapleStory(모바일 도메인), PUBG Daum BBS. 모두 `requests` + `BeautifulSoup`로 처리.
5. **비공식 JSON 추가**: NC plaync 계열은 브라우저 DevTools Network → XHR 필터로 백킹 API URL 추출 → `User-Agent`만 정상 브라우저로 맞춰서 호출. HoYoLAB JSON, Stove `api.onstove.com`도 동일.
6. **인벤 게임별 서브도메인**: HTML 구조가 비교적 안정적이지만 selector 변경 사례 보고됨(예: 인벤 페이지네이션이 query → path 스타일로 변경). selector를 매주 점검하는 CI canary 테스트 작성(expected_count 검증).

### Stage 3 (5~8주, 봇 차단된 사이트 단계적 추가)
7. **아카라이브/디시인사이드**: 한국 거주 IP 필요. AWS·GCP에서 돌리면 거의 확실히 막힘. 옵션 (a) 가정용 회선의 자가 서버, (b) 한국 주거용 프록시 서비스(Bright Data 등). 폴링 간격 최소 5분 이상 보수적으로. **디시인사이드는 모바일 도메인 사용 시 차단 강도가 약함**.
8. **Cloudflare 우회 라이브러리 단계적 도입**: `cloudscraper`(가벼움, 단순 JS 챌린지만) → `curl-impersonate`(JA3/JA4 위장) → `Playwright + playwright-stealth` → Scrapfly/ZenRows 같은 상용 API. 상용 서비스는 자체 마케팅에서 95~98%대 성공률을 표방하나 독립적 검증치는 부족하므로 PoC로 확인. **상용 도입 손익분기는 보통 사이트 수 ≥ 30이거나 일 폴링 ≥ 10K** 정도.
9. **네이버 카페**: 운영자 사전 동의가 가능한 경우만. Selenium에 로그인 세션 저장(`storage_state`), 캡차 발생 시 알람 보내고 수동 해소.

### 제외 권장
- **Twitter/X**: ROI 안 나옴. 비용($200~$5,000/월, 신규는 pay-per-use) 대비 게임 공지는 거의 다 다른 채널에도 올라옴. 정 필요하면 Nitter/RSSHub 셀프호스트로 fallback.
- **Naver Cafe**: 운영자 동의 없는 자동화 폴링은 ToS 위반 가능. 사용자가 자기 카페만 모니터링하는 경우 외엔 비추.

### 이 권장사항을 바꿀 임계점 (Thresholds)
- Cloudflare 사이트가 등록 사이트의 30% 초과 → Scrapfly/ZenRows 같은 상용 API 도입 고려
- 사이트별 selector 깨짐 알람이 주 3건 이상 → arXiv 2601.06301 ELA 패턴(Claude Computer Use / Simular.ai)으로 fallback 도입
- 폴링 대상이 100개 초과 → 단일 워커 → 작업 큐(Celery/Arq) + 사이트별 rate limit 토큰 버킷으로 재설계
- 한국 게임사 비공식 JSON 엔드포인트가 한 달에 2회 이상 깨짐 → HTML fallback과 함께 이중 코드 경로 운영
- Twitter/X 데이터가 정말 필요해진다면 → Apify/SociaVault/twitterapi.io 같은 서드파티(공개 데이터 한정, $0.45~$0.70/1K 트윗) 우선 검토

## Caveats

1. **"비공식 JSON 엔드포인트는 언제든 사라질 수 있다."** plaync.com `api.plaync.com`, Stove `api.onstove.com`, HoYoLAB `bbs-api-os.hoyolab.com` 모두 명시적 공개 약속이 없으며, 게임사가 임의로 스키마를 바꿔도 통보 의무가 없다. 봇은 반드시 fallback 경로(HTML 스크래핑) 또는 무응답 감지 알람을 함께 구현해야 한다.
2. **arXiv 2601.06301은 2026년 1월 사전출판본**으로 동료심사 완료 전이다. Table 2의 성공률 수치(BeautifulSoup 0.93/0.80, Simular.ai 1.00/1.00/0.63/0.70/0.10 등)는 그 시점·그 프롬프트 조건에서의 측정값이며, 사이트 측 anti-bot 정책 변경에 따라 빠르게 변한다.
3. **2026년 5월 기준 정보로 작성**되었으나, Cloudflare 우회 도구(Cloudscraper, FlareSolverr, curl-impersonate)의 효과는 분기 단위로 달라진다. 상용 서비스의 "Cloudflare 우회 성공률 95%+" 같은 자체 발표 수치는 마케팅 측면이 강하므로 자체 PoC로 검증 필요.
4. **법적·ToS 측면**: 미국에서는 공개 데이터 스크래핑이 hiQ v. LinkedIn(9th Circuit) 등에서 합법 판결된 사례가 있지만, 한국에서는 정보통신망법·저작권법·DB권 등 별도 검토 필요. 특히 네이버 카페·디시인사이드는 자동화에 대한 명시적 제한이 존재. 봇 운영 시 사이트별 `robots.txt` 준수와 보수적인 rate limit이 최소 안전선.
5. **매너 있는 봇 운영이 장기 안정성의 핵심**: "새 글 알림" 봇은 보통 사이트 측에 가치를 더해주는데도(트래픽 유발), 갑작스러운 폴링 폭주는 DDoS로 오인된다. 폴링 간격 ≥ 5분, User-Agent에 연락처 명시, `If-Modified-Since`/`ETag` 활용, 응답이 304이면 추가 요청 자제 — 이런 매너 있는 패턴이 차단을 가장 효과적으로 피하는 방법.
6. **본 보고서의 한국 게임사 비공식 JSON 엔드포인트 URL 패턴은 2026년 5월 기준 DevTools 관찰·공개 GitHub 레포 기반**이며 일부는 직접 호출 검증을 거치지 않았다. 실제 사용 전 각 엔드포인트의 응답 스키마·인증 요구사항을 자체 PoC로 확인할 것. 또한 Twitter/X의 종량제(2026년 2월 6일 발효) 단가는 출처마다 약간씩 차이가 있어 ($0.005~$0.010/request 등) 실제 청구는 X 개발자 포털 견적 도구로 직접 확인 권장.
