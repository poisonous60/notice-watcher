# 배포 가이드 — N100 미니PC + Discord 봇

게시판 크롤링 엔진 + Discord 봇 알림을 항상 켜둔 미니PC(N100, Arch/Nyarch 가정 — 우분투/데비안이면 `pacman`→`apt`)에서
systemd 로 상시 운영하기. 화면은 꺼두고, 모니터링은 SSH + 봇 `/status` 로.

```
N100 미니PC (한국 주거지 IP — arca/dcinside 차단 회피에 유리)
  ├─ systemd notice-bot.service   : discord.py 봇 (게이트웨이 상주, 아웃바운드만)
  │     /watch <url> [filter] [schedule] [here] [notify_empty] [article_url]  /preview <url> [article_url]  /list  /unwatch <slug>  /status
  │     /watch → register.py 를 subprocess 로 실행(chromium 락) → 구독을 output/bot.sqlite3 에 저장
  └─ systemd notice-poll.timer    : 매일 08:20 KST → poll_and_notify.py (poll.py → notify.py --heartbeat)
        poll.py    : 등록 사이트 폴링 → 새 글 diff → output/collected/<ts>/{<slug>.new.json, poll_result.json}
        notify.py  : 새 글 → Gemini 요약 → (구독별 필터) → realtime 즉시 DM/채널 · 'HH:MM' 다이제스트 · notify_empty=1 이면 새 글 없을 때 '새 공지 없음' 1줄
```

## 0. 준비물 (사람 손)

### 0-1. Discord 봇 앱 만들기 (네 Discord 계정으로만)
1. https://discord.com/developers/applications → **New Application** → 이름.
2. 좌측 **Bot** → **Reset Token** → 토큰 복사 (= `BOT_TOKEN`, 안전한 곳에). "Message Content Intent" 는 꺼도 됨(슬래시만 씀).
3. 좌측 **OAuth2 → URL Generator** → scopes: `bot` + `applications.commands` 체크 → bot permissions: `Send Messages`(DM 은 권한 불필요) → 생성된 URL 로 네 (테스트)서버에 봇 초대.
4. 내 유저 ID: Discord 설정 → **고급 → 개발자 모드 ON** → 내 프로필 우클릭 → "사용자 ID 복사" (= `OWNER_USER_ID`, 에러 DM 받을 사람).
5. (선택) 서버(길드) ID 도 같은 방식으로 (= `GUILD_ID`, 슬래시 명령 즉시 등록용; 비우면 글로벌 등록은 ~1시간 걸림).

### 0-2. Gemini API 키
- 이미 repo 에 `GEMINI_API_KEY.md` 가 있으면 그대로 쓰면 됨. (없거나 429 잦으면) https://aistudio.google.com/apikey 에서 발급 → `GEMINI_API_KEYS=키1,키2`.

### 0-2b. Google Safe Browsing API 키 (필수)
`/watch`·`/preview`(처음 보는 사이트) 직전에 URL 을 검사하는 **URL 게이트**(`bot/url_gate.py`)의 악성 URL 검사에 쓴다. **비어 있으면 게이트가 fail-closed 라 신규 사이트 등록이 전부 거부된다**(이미 등록된 사이트의 폴링·알림은 영향 없음).
- https://console.cloud.google.com → 프로젝트 만들기/선택 → **API 및 서비스 → 라이브러리 → "Safe Browsing API" → 사용 설정** → **사용자 인증 정보 → 사용자 인증 정보 만들기 → API 키** → 키 복사 → `.env` 의 `SAFE_BROWSING_API_KEY=` 에.
- 만든 직후 그 키의 **API 제한**에서 "Safe Browsing API" 만 허용으로 좁혀두면 키가 새도 피해 최소화(권장).
- billing 계정 불필요(v4 Lookup 은 완전 무료, 비상업 한정 — 이 봇 해당). v4 는 2027-03-31 종료 예정이지만 그땐 `is_url_safe()` 한 함수만 v5/Web Risk 로 교체하면 됨.
- 단독 점검: `.venv/bin/python -m bot.url_gate "https://testsafebrowsing.appspot.com/s/malware.html"` → `reason=malicious` 나오면 키 정상. `--no-gsb` 면 키 없이 구조/SSRF/블랙리스트만 검사.

### 0-3. N100 에 SSH 켜기 (배포·로그 확인용)
```bash
# N100 에서:
sudo pacman -S openssh        # (없으면) — 우분투면 보통 이미 있음 (apt install openssh-server)
sudo systemctl enable --now sshd
ip a                          # 내 LAN IP 확인 (예: 192.168.0.42)
# dev 박스(Windows)에서:
ssh-keygen -t ed25519         # (키 없으면)
ssh-copy-id poiso@192.168.0.42   # 또는 ~/.ssh/id_ed25519.pub 내용을 N100 의 ~/.ssh/authorized_keys 에 붙여넣기
ssh poiso@192.168.0.42        # 비번 없이 들어가지면 OK
```
(집 밖에서도 보려면) N100·dev박스·노트북에 [Tailscale](https://tailscale.com) 무료 설치 → `tailscale up` → `ssh poiso@<머신이름>` 어디서든.

### 0-4. (선택) Healthchecks.io
https://healthchecks.io 무료 가입 → check 생성 → ping URL 을 `.env` 의 `HEALTHCHECK_PING_URL` 에. 폴링이 조용히 죽으면 이메일.

```bash
cp deploy/.env.example .env
nano .env          # BOT_TOKEN, GEMINI_API_KEYS, SAFE_BROWSING_API_KEY, OWNER_USER_ID(, GUILD_ID) 채움
```

### 스모크 (systemd 등록 전 손으로)
```bash
.venv/bin/python scripts/poll.py                 # 등록된 사이트(처음엔 configs/ 의 예제들) 폴링 — new=0 이 정상
.venv/bin/python scripts/notify.py --dry-run     # 발송 메시지 미리보기 (구독 없으면 거의 아무 것도 안 함)
```

## 2. systemd 로 상시 운영

`deploy/*.service` / `deploy/notice-poll.timer` 안의 `User=` / `WorkingDirectory=` / `EnvironmentFile=` / `ExecStart=` 경로를 본인 환경(사용자명, clone 위치)에 맞게 수정한 뒤:

```bash
sudo cp deploy/notice-bot.service deploy/notice-poll.service deploy/notice-poll.timer /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now notice-bot.service notice-poll.timer
```

### 확인 (전부 SSH 로)
```bash
systemctl status notice-bot                       # active (running)
journalctl -u notice-bot -f                       # 봇 로그 실시간 — "logged in as ..." / "synced N commands" 나오면 OK
systemctl list-timers notice-poll.timer           # 다음 폴링 예정 시각
sudo systemctl start notice-poll.service          # 폴링 즉시 1회
journalctl -u notice-poll --since "10 min ago"
```
Discord 에서 `/status` → 등록 config 수 / 구독 수 / 마지막 폴링 시각 / 깨짐·실패 slug / 마지막 에러. (에러 나면 봇이 `OWNER_USER_ID` 에게 DM.)

### 재배포 (코드 수정 후)
```bash
cd notice-watcher && git pull
sudo systemctl restart notice-bot.service         # 봇 재시작 (timer 는 다음 발화 때 새 코드 자동 반영)
sudo systemctl start notice-poll.service          # 폴링 즉시 테스트하려면
```

## 3. 사용 (Discord)

- `/watch <게시판 목록 URL> [filter] [schedule] [here] [notify_empty] [article_url]` — 등록 + 구독.
  - `filter` (선택): 자연어. 예) `점검 공지는 빼고 신규 콘텐츠/이벤트만`. 비우면 새 글 전부.
  - `schedule` (선택): `realtime`(기본, 폴링 때마다 바로) 또는 `HH:MM`/`HH`(매일 그 시각 KST 에 하루치 모아 다이제스트). 예) `09:00`, `9`.
  - `here` (선택): 켜면 이 채널에 발송, 끄면(기본) 내 DM.
  - `notify_empty` (선택): 켜면 폴링했는데 새 글 없을 때도 '새 공지 없음' 1줄. realtime 일 때만.
  - `article_url` (선택): 처음 등록하는 사이트가 자동 분석에 실패할 때 — 그 게시판의 **실제 글 하나 URL** 을 같이 주면 분석 성공률이 올라감(register.py 가 그 글페이지를 직접 re-probe 해서 본문 API/구조를 잡음). 이미 등록된 사이트면 무시됨.
  - 처음 보는 사이트는 등록 전에 **URL 게이트**(`bot/url_gate.py`)를 통과해야 함 — http(s) 형식·인증정보 없음·IP 리터럴 아님 / SSRF(내부망·로컬 주소로 해석되는 도메인 거부) / SNS·유튜브·축약링크(bit.ly 등)·파일 직링(.pdf·.zip…) 거부 — 이 블랙리스트는 `bot/url_blacklist.json` 에서 수정(그룹별 메시지·도메인 목록) / Google Safe Browsing 악성 URL 검사. 막히면 그 자리에서 사유 안내(probe 안 돌림). `article_url` 도 같이 검사함.
  - 게이트 통과 후 config 생성에 수 분 걸림(probe + Playwright + Gemini). 자동 안 되면 "손어댑터 필요" 안내가 옴.
  - 등록 성공 시 **예시 알림 1건**을 같이 보여줌(그 게시판 최신 글 요약).
- `/preview <URL> [article_url]` — 등록·구독 없이 그 게시판 최신 글 요약 예시만 (ephemeral). 처음 보는 사이트면 config 생성 후 보여줌(느림). `article_url` 은 `/watch` 와 동일(처음 분석할 때만 의미 있음).
- `/list` — 내 구독 목록. `/unwatch <slug 또는 URL>` — 구독 해제(config 파일은 남김).
- `/status` — 봇/폴링 상태.

## 4. 동작/제약 메모

- **상태 영속화**: `output/poll_state/<slug>.json`(본 글 post_id 집합·깨짐 카운터), `output/bot.sqlite3`(구독·다이제스트 대기열·발송 기록) — N100 디스크에 그대로 남음. 박스가 잠깐 꺼져도 켜지면 그동안 쌓인 새 글 전부 잡음(지연만, 손실 없음).
- **`configs/<slug>.json`** 은 repo commit 대상(백업·리뷰용). `output/` 는 전부 gitignore.
- **chromium 락**: `register.py`(probe) 와 `poll.py`(재-probe / arca 등 playwright_html·handwritten 폴링) 가 동시에 chromium 을 안 띄우게 파일 락(`output/.chromium.lock`). `/watch` 가 폴링 타이머와 겹치면 한쪽이 잠깐 대기.
- **politeness**: 엔진이 요청 간 3~6s + jitter 강제, 같은 host 직렬화. dcinside 는 robots Crawl-Delay 30s 반영(폴링 1회당 요청 직전에만 걸림). 폴링 주기 = **하루 1회 08:20 KST**(`notice-poll.timer`, `OnCalendar=*-*-* 08:20:00 Asia/Seoul`; 2026-05-11 이전엔 매시). 더 자주/덜 자주 하려면 `~/.config/systemd/user/notice-poll.timer` 의 `OnCalendar` 수정 후 `systemctl --user daemon-reload && systemctl --user restart notice-poll.timer`.
  - ⚠️ **다이제스트·notify_empty 는 폴링이 돌 때만 발송됨**(별도 cron 없음). 폴링이 하루 1회(08시)면: `notify_empty`(realtime) 는 매일 08시에 옴 — 의도대로. 하지만 다이제스트(`schedule=HH:MM`) 는 `flush_digests` 가 `HH == 현재시(時)` 일 때만 비우므로, 폴링 시각(08시)과 다른 시각의 다이제스트는 **영영 안 비워짐**. 다이제스트 구독을 쓸 거면 (a) 다이제스트 시각을 폴링 시각과 맞추거나, (b) 폴링을 더 자주(예: 매시) 돌리거나, (c) `notify.py` 의 `flush_digests` 를 "지난 시각도 비우기"로 고치기. 현재 다이제스트 구독은 0건이라 당장 문제는 없음.
- **URL 게이트**(`bot/url_gate.py`, `_ensure_registered` 안에서 호출): 처음 보는 사이트만 검사(이미 등록된 사이트는 안 거침). 순서 = ①구조 검증(http(s)/인증정보 없음/IP 리터럴 거부/제어문자 없음) ②정책 블랙리스트 — **`bot/url_blacklist.json`** 의 `groups[]`(각 그룹 `{name, message, host_suffix[], path_ext[]}`, 위에서부터 첫 매치의 message 로 거부), 네트워크 호출 없음, 파일 편집하면 다음 검사 때 자동 반영(재시작 불필요), 깨지면 `_DEFAULT_BLACKLIST` 폴백 ③SSRF(host IDNA→DNS 해석, 사설/loopback/link-local/reserved/multicast IP 면 거부; gaierror→dns_failed) ④Safe Browsing(v4 threatMatches:find POST 1회, 4s, 재시도 없음, **fail-closed** — 키 없음/네트워크 오류/non-200/파싱 실패면 `gsb_error` 로 거부, matches 있으면 `malicious` 거부; 둘 다 OWNER DM). 거부는 `journalctl` 에 `[url_gate] reject ...` + `/status` 의 "URL 게이트 거부(24h)" 카운터(in-process, 재시작 시 리셋) + blacklist 출처 표시. triage_queue 엔 안 쌓음. 한계: 제출된 URL 문자열만 검사 — 리다이렉트(→SNS/→사설IP)·DNS rebinding(TOCTOU) 은 완전히 못 막음; 단독 점검은 `python -m bot.url_gate "<url>" [--no-gsb] [--no-dns]`.
- **봇이 꺼져 있어도** 알림은 나감 — `notify.py` 가 봇 토큰으로 Discord REST 직접. 봇 프로세스는 슬래시 명령 *수신* 용.
- **차단 시 대비**: arca 가 Cloudflare 로 막히면 `configs/arca_akendfield.json`(handwritten, playwright-stealth)로 등록. 다른 사이트가 막히면 ScraperAPI 무료 등 프록시 검토(`docs/SKKU 공지 알림 자동화 시도 기록.md` §6).
- **SKKU 공지 봇**(`poisonous60/skku-notice-bot`)은 별도 repo + GitHub Actions 그대로 — 이주는 나중에. (로컬엔 없음. 손볼 일 있으면 프로젝트 밖에 `gh repo clone poisonous60/skku-notice-bot` 으로 다시 clone.)

## 부록 A — sudo 없이 (user systemd) — 실제 N100 배포가 이 방식

`/etc/systemd/system/` 에 쓰려면 sudo 가 필요한데, 그게 없거나 귀찮으면 **사용자 systemd 유닛**으로:

```bash
# 1) 로그아웃해도 서비스가 살아있게 (헤드리스 박스 필수)
loginctl enable-linger "$USER"            # sudo 없이도 보통 됨; loginctl show-user "$USER" -p Linger 로 yes 확인

# 2) ~/.config/systemd/user/ 에 유닛 3개 (deploy/*.service 를 복사하되:
#    - User= 줄 삭제, WorkingDirectory/EnvironmentFile/ExecStart 경로를 본인 홈으로
#    - notice-bot.service 의 WantedBy=multi-user.target → WantedBy=default.target
#    - notice-bot.service [Unit] 에 StartLimitIntervalSec=300 / StartLimitBurst=5 권장(토큰 없을 때 크래시루프 방지)
mkdir -p ~/.config/systemd/user
cp deploy/notice-bot.service deploy/notice-poll.service deploy/notice-poll.timer ~/.config/systemd/user/
nano ~/.config/systemd/user/notice-bot.service     # 위 수정 적용 (다른 둘도 경로만 수정)

systemctl --user daemon-reload
systemctl --user enable --now notice-poll.timer
systemctl --user enable --now notice-bot.service   # .env 에 BOT_TOKEN 채운 뒤에!

# 로그/상태 (--user 붙임; 로그는 --user-unit 으로 — 환경에 따라 `journalctl --user -u` 가 "No journal files" 날 수 있음)
systemctl --user status notice-bot
journalctl --user-unit notice-bot.service -f         # 봇 로그 실시간
journalctl --user-unit notice-poll.service -n 50     # 폴링 로그
systemctl --user list-timers notice-poll.timer
systemctl --user start notice-poll.service           # 폴링 즉시 1회
```
재배포: `cd ~/notice-watcher && git pull && systemctl --user restart notice-bot.service`.

봇 초대(슬래시 명령 보이게): `https://discord.com/oauth2/authorize?client_id=<봇 client_id>&scope=bot+applications.commands&permissions=2048` 로 서버에 초대 → `systemctl --user restart notice-bot.service` (on_ready 가 그 길드에 즉시 명령 동기화).

## 부록 B — 비공개 repo 를 N100 에서 clone (deploy key)

repo 가 private 면 N100 에서 HTTPS clone 이 인증을 못 한다. 읽기전용 deploy key 로:
```bash
# N100 에서:
```
