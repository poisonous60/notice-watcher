# 디스코드 메시지 톤 가이드

봇이 Discord 채널/DM 으로 **일반 사용자**에게 보이는 메시지의 톤·문체·포맷을 통일한다. 새 메시지를 추가하거나 기존 메시지를 손볼 때 이 가이드에 맞춘다.

## 1. 적용 범위

이 가이드는 **사용자 향 메시지**에만 적용된다. 구체적으로:

| 위치 | 적용? |
|---|---|
| `bot/main.py` 슬래시 명령 응답 (`/watch`·`/preview`·`/list` 등 — 모든 사용자) | ✅ |
| `bot/worker.py` 잡 ack 갱신 (`edit_channel_message`) | ✅ |
| `bot/url_gate.py` `UrlRejected.msg` (사용자에게 노출됨) | ✅ |
| `scripts/notify.py` 새 글 알림 본문 | ✅ |
| `bot/admin.py` owner-only `ephemeral=True` 응답 | ❌ (owner 전용 — 간결한 평서체 허용) |
| `_dm_owner(...)` / `dm_owner(...)` 운영자 DM | ❌ (기술적 표현 허용) |
| `scripts/*.py` CLI `print(...)` 출력 | ❌ (개발자 향) |
| `register.py` 의 `_policy_check`·`_board_shape_check` 같은 print 메시지 | ❌ (worker 가 ack 로 따로 친절 문장을 만든다) |

판단 기준: **봇 명령을 쓴 일반 사용자가 결과로 보게 되는 메시지인가?** 그러면 이 가이드.

## 2. 기본 톤 — 해요체

종결어미는 `~어요/~예요/~네요/~주세요` 통일.

- 좋음: "URL 이 비어 있어요." / "잠시 후 다시 시도해 주세요." / "등록 완료했어요."
- 피함: "URL 이 비어 있습니다." / "다시 시도하십시오." / "등록 완료." (← 합니다체·평서명사형은 owner-DM/CLI 영역으로)

예외:
- 헤더(짧은 한 줄 제목)는 동사 없이 명사구 OK — `✅ 등록 완료 — \`<slug>\`` 같은 식. 행동 요청·설명이 붙으면 그 문장은 해요체.

## 3. 이모지 어휘 (의미 고정)

| 이모지 | 쓰는 곳 | 의미 |
|---|---|---|
| ✅ | 헤더 | 성공 (등록/구독/처리) |
| ⚠️ | 헤더 | 실패·거부 (사용자가 다시 해야 함) |
| ❌ | 헤더 | 입력 자체가 잘못 (URL 형식 X 등 즉시 거절) |
| 🔧 | 헤더 | 진행 중 — 분석/처리 단계 |
| ⏳ | 헤더 | 진행 중 — 외부 호출 대기 (LLM·HTTP) |
| 📋 | 본문 라벨 | "예시 알림" 등 첨부 라벨 |
| 📥 | 본문 라벨 | 큐 추가 상태 |
| 🛑 | 헤더 | 사용자 본인이 취소·중단한 결과 |

새 이모지 추가 자제. 의미가 겹치면 위 8개로 매핑.

## 4. 영문 기술 용어

영문 그대로 노출한다 (현재 코드 컨벤션). 한글로 풀지 않는다.

- 좋음: `URL`, `slug`, `config`, `baseline`, `probe`, `XHR`, `RSS`, `JSON`
- 피함: "링크 주소", "식별자", "설정 파일", "기준치"

이유: 사용자 = 개발자 / 게임 동호회 운영자 등 기술 친숙층. 한글 번역이 오히려 어색하고, 봇 메뉴/명령(`/watch`·`/preview`)도 영문이라 일관됨.

## 5. 단정 vs 추측

봇 휴리스틱이 확신 못 하는 결과는 **추측 표현** 으로.

- 휴리스틱·자동 판정 결과: "…인 것 같아요" / "…인 것으로 보여요" / "보통은 …"
- 명확한 입력 오류: "…이 비어 있어요" / "…이 잘못됐어요" (단정 OK — 사실)
- 외부 정책 결정: "…이라서 등록할 수 없어요" (단정 OK — 정책)

예:
- 좋음: "이 URL 은 게시판 형식이 아닌 것 같아요. 게시판/공지 *목록* 페이지 URL 을 주세요."
- 피함: "이 URL 은 게시판이 아닙니다." (휴리스틱이라 100% 보장 X)

## 6. 식별자·링크 포맷

- `slug` 는 항상 인라인 코드 백틱: `` `host_syosetu-colomo-_root_2ff18e94` ``
- URL 은 그냥 평문 (Discord 가 자동 미리보기). 백틱·괄호 X. 길이 제한 시 끝부분 `…` 생략.
- 코드 블록(```` ``` ````)은 다중행 오류 출력·tail 같은 raw 텍스트일 때만. 짧은 사용자 메시지에 코드 블록 X.

## 7. 길이·줄바꿈

- 헤더 1줄 + 보강 N줄 형태. 보강 없으면 헤더만.
- 보강은 글머리 ` • ` (가운뎃점) 또는 빈 줄 + 본문.
- 길이 한도: 자동 ack 갱신은 한 화면 (~10줄). 길어지면 코드 블록 또는 별도 첨부 안내.

예 (현재 `_post_register_success` — 그대로 모범):
```
✅ 등록 완료 — `<slug>`
• baseline 33건(이 글들은 '새 글' 아님)
• 필터: 없음(새 글 전부)
• 발송: 폴링 직후 즉시
• 알림: 이 채널
• 새 글 없을 때도 알림: 아니오

📋 **예시 알림** (이런 형식으로 옵니다):
…
```

## 8. 안내 끝에는 다음 행동을

거부·실패 메시지는 항상 "다음에 뭘 해야 할지" 한 줄 안내로 닫는다.

- 좋음: "…URL 이 비어 있어요. 게시판/공지 목록 페이지 URL 을 주세요."
- 좋음: "Safe Browsing 검사를 못 했어요 — 잠시 후 다시 시도해 주세요."
- 피함: "Safe Browsing 검사 실패." (다음 행동 X)

`/report`·운영자 문의로 유도해야 하면 그것도 명시 ("계속 같은 문제면 `/report` 로 알려 주세요").

## 9. 단어 선택

| 선호 | 피함 | 이유 |
|---|---|---|
| 등록 | 추가/생성/저장 | 봇 명령(`/watch`)·내부 용어 통일 |
| 구독 | 알림 신청/팔로우 | 〃 |
| 폴링 | 주기 조회/체크 | 사용자가 `/list` 등에서 자주 봄 |
| 잠시 후 | 나중에/추후 | 명확 |
| 손어댑터 | custom adapter/수동 어댑터 | 프로젝트 용어 |

## 10. 점검 체크리스트 (PR 전)

새 사용자 향 메시지를 추가했다면:

- [ ] 1. 적용 범위 표 기준 "사용자 향" 인가?
- [ ] 종결어미 해요체?
- [ ] 이모지가 §3 표의 8개 중 하나?
- [ ] 단정/추측 §5 기준에 맞나?
- [ ] slug 백틱·URL 평문?
- [ ] 거부/실패면 다음 행동 안내가 있나?

`grep` 으로 새 문자열 후보 확인: `bot/` 안의 `await .*send_message\|edit_channel_message\|edit_original_response\|UrlRejected(` 줄.
