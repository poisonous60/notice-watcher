# 사이트별 구현 방침

각 사이트의 **로그인 처리 방식**과 **현재(2026-05) 시점의 진입점 검증 결과**를 정리한다.

---

## 1. 로그인 처리: 방법 C (Playwright storage_state) 채택

로그인이 필요한 페이지(아카라이브, 로그인 한정 디시 갤러리 등)는 **Playwright headful 브라우저로 사람이 한 번 로그인 → `storage_state` 저장 → 이후 자동 폴링이 그 상태를 복원**하는 방식을 사용한다.

### 1-1. 동작 원리

Hitomi-Downloader가 임베디드 Chromium 창을 띄워 로그인시키고 쿠키를 캡처해 재사용한 것과 정확히 동일한 방식이며, 이를 Playwright로 재구현한 것.

### 1-2. 구현 패턴

**최초 1회 — 사람이 로그인:**

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=False)
    ctx = browser.new_context()
    page = ctx.new_page()
    page.goto("https://arca.live/u/login")
    input("로그인 끝나면 엔터 (캡차/2FA 포함 사람이 직접 처리)")
    ctx.storage_state(path="state/arca_state.json")
```

**이후 자동 폴링 — 상태 복원:**

```python
ctx = browser.new_context(storage_state="state/arca_state.json")
```

### 1-3. 채택 이유

| 항목 | 방법 A (수동 쿠키 복사) | 방법 B (browser-cookie3) | **방법 C (Playwright storage_state)** |
|---|---|---|---|
| 캡차/2FA 대응 | ✓ | ✓ | ✓ |
| Cloudflare cf_clearance 동시 캡처 | ✗ | ✗ | **✓** |
| 서버 배포 가능성 | ✓ | ✗ (브라우저 필요) | **✓** |
| 자동 로그인 위험 (사람인 판례) | 없음 | 없음 | **없음** |
| 비밀번호 코드 보관 | 불필요 | 불필요 | **불필요** |

방법 C는 cf_clearance 쿠키와 로그인 쿠키를 **한 번에** 캡처하므로 아카라이브에 특히 적합하다.

### 1-4. 운영 규칙

- `storage_state` 파일 경로: `state/{사이트}_state.json`
- `.gitignore`에 `state/` 추가 (쿠키는 절대 커밋 금지)
- 401/403 + 로그인 페이지 리디렉트 감지 시 "쿠키 갱신 필요" 알림 발송
- 일 1회 폴링 기준 보통 분기당 1회 정도 갱신 필요

## 2. 디시인사이드 진입점 (검증 결과)

조사 문서의 모바일/앱 API 권장은 **2022년 이전 정보 기반**이라 현재 신뢰도가 낮다. 2026-05 시점 직접 검증 결과는 다음과 같다.

### 2-1. 검증 결과

| 후보 진입점 | 상태 | 권장도 |
|---|---|---|
| `m.dcinside.com/api/gall_list.php` | **HTTP 404** (엔드포인트 폐기/변경) | ✗ |
| `app.dcinside.com/api/gall_list_new.php` (OpenDC 문서) | OpenDC 저장소 정지, 검증 불가 | ✗ |
| `eunchuldev/dcinside-python3-api` (dc_api 라이브러리) | **마지막 커밋 2022-07** (3년 9개월 정지) | ✗ |
| `gall.dcinside.com/board/lists/?id={갤}` (PC 웹) | **정상 작동, 비로그인 가능** | **✓ 1차 진입점** |
| 글 본문 `/board/view/?id={갤}&no={번호}` | **정상** | **✓** |

### 2-2. 채택 진입점

**1차 (목록):**
```
GET https://gall.dcinside.com/board/lists/?id={갤러리}
```
- HTML 정적 파싱 (table 기반: `<tr>` 행에 번호/제목/글쓴이/작성일/조회/추천)
- 비로그인 가능

**1차 (본문):**
```
GET https://gall.dcinside.com/board/view/?id={갤러리}&no={글번호}&page=1
```

### 2-3. 헤더 (필수)

```
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/...    # 평범한 데스크톱
Referer: https://gall.dcinside.com/
Accept-Language: ko-KR,ko;q=0.9
```

> **주의**: 조사 문서가 권장한 `User-Agent: dcinside.app` + `Referer: http://www.dcinside.com`은 폐기된 모바일 API 전용이었음. PC 웹 진입점에는 평범한 Chrome UA를 쓴다.

### 2-4. 실패 시 fallback

`requests`/`httpx`가 막히면 → 다음 폴링 회차에 Playwright (박종훈 블로그 2023.7 패턴 참조). 같은 회차 내 실시간 escalation은 금지(우회 시도로 보일 수 있음).

## 3. 아카라이브 진입점

### 3-1. 진입점

| 진입점 | 비고 |
|---|---|
| `https://arca.live/b/{채널}` (HTML 목록) | 1차 시도 |
| `https://arca.live/b/{채널}/{번호}` (HTML 본문) | 1차 시도 |
| `https://arca.live/api/app/list/channel/{채널}` (JSON) | 위가 실패 시 보조 — Cloudflare 보호하 |
| Playwright + storage_state | 위 둘 다 실패 시 fallback (방법 C 결과물 재사용) |

### 3-2. 로그인 필수 케이스

- 성인 등급 채널: **로그인 + 성인 인증** 모두 필요 → 방법 C 사용
- 한국 IP 차단 채널 (HTTP 451): 정책 차단이라 우회 불가 (영업적 우회는 사람인 판례상 위험 가중)

### 3-3. 요청 간격

같은 호스트 호출 사이 **5초 이상 + jitter ±30%** (아카라이브는 4번째 요청쯤 Cloudflare 챌린지가 뜨는 것으로 사용자 보고됨).

## 4. 게임사 공식 공지

- 거의 모두 SSR HTML, 비로그인 공개
- `httpx` + BeautifulSoup으로 충분
- Cloudflare/봇 보호 사실상 없음
- 본문 정제가 귀찮으면 `https://r.jina.ai/{원본URL}` 한 줄 변환으로 마크다운화 가능
