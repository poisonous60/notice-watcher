# 신규 사이트 어댑터 추가 가이드

이 문서는 **새 게시판/공지 사이트에 대한 어댑터를 추가**할 때의 표준 워크플로우다.
새 대화 세션에서 컨텍스트가 없는 상태로도 그대로 따라 할 수 있게 작성했다.

> **먼저 자동 등록부터 시도해 봐라.** `register.py` 는 등록 전에 **첫 글 페이지를 Playwright+HAR 로 re-probe**(본문 JSON API 후보·렌더 DOM 확보) + probe 신호로 목록 전략 hint 를 미리 주는 preflight 를 거치므로 — 본문이 SPA/JS 렌더면 (a) 본문을 주는 JSON XHR 이 있으면 `article.fetch_kind:"json"` config, (b) 없으면 `strategy:"playwright_html"` config 로 자동 전환을 시도하고, 목록이 JS 렌더면 `httpx_json`/`playwright_html` 로 유도한다. 그래도 `<slug>.FAILED.json` 이 나면 그제서야 이 가이드(손어댑터)다.
> 또 — 손어댑터(`adapters/<site>.py` 파이썬 코드)가 정말 필요한 건 *config 스키마로 표현이 안 되는* 경우(Cloudflare 챌린지가 강해서 stealth 가 필요하다거나, 클릭/스크롤 후에야 로드되는 데이터 등)다. **단순히 본문이 JS 렌더일 뿐이거나, 목록 링크가 직접 접근 가능한 글 URL 과 다를 뿐이면(예: 마비노기) 손어댑터 말고 손작성 JSON config 만 써서 `register.py --config` 로 등록**해도 된다.
> ⚠️ **어떤 종류의 실패인지부터 판별해라 → `docs/config 자동생성 실패 케이스.md`** (`.FAILED.json` 의 `last_feedback` 의 `[FAIL] <체크명>` 으로 분류 + 케이스별 대응). 이 가이드는 그 문서가 "손어댑터 필요" 라고 한 경우의 절차다.

---

## 0. 워크플로우 한눈에

```
[1] probe 실행 → [2] 산출물 검증 → [3] 결과 해석 → [4] 어댑터 작성 → [5] 데모로 검증
```

각 단계는 *이전 단계의 raw 산출물*을 사람이 직접 읽어 확인하는 것을 전제로 한다.
도구가 결론을 짓는 게 아니라 사람이 데이터를 보고 판단한다.

## 2. Step 1 — probe 실행

대상은 **목록 URL 하나**. 한 번에 한 URL만 받는다.

### 2-1. 기본 명령

```bash
python scripts/probe.py "<목록 URL>"
```

자주 같이 쓰는 옵션:

| 옵션 | 언제 |
|---|---|
| `--no-crawl4ai` | crawl4ai 미설치/속도 절약 |
| `--no-paid` | 유료 API 키 없을 때 (또는 명시적 비활성화) |
| `--no-replay` | HAR JSON API 재현 시도 스킵 |
| `--no-headless` | Playwright 자체 비활성 (httpx만) |
| `--login` | 분류와 무관하게 헤드풀 로그인 강제 (성인 채널 등) |
| `--no-login` | LOGIN_REQUIRED 자동 트리거 비활성 |
| `--extra-header "K=V"` | 사용자 정의 헤더 한 줄 더 시도 |
| `--scraperapi-key`, `--scrapingbee-key`, `--zyte-key`, `--brightdata-proxy` | 유료 API 키 직접 주입 |

### 2-2. 사전 준비 (1회)

```bash
pip install -r requirements.txt
playwright install chromium
```

### 2-3. 자주 쓰는 명령 예시

```bash
# 무료/가벼운 진단만
python scripts/probe.py "<URL>" --no-crawl4ai --no-paid --no-replay

# 로그인 필요 채널 강제 진입
python scripts/probe.py "<URL>" --login

# 디버그 (Playwright headful)
python scripts/probe.py "<URL>" --headful-debug
```

## 3. Step 2 — 산출물 검증

`output/probe/<slug>/` 디렉토리를 사람이 직접 본다. 핵심 파일 5개.

### 3-1. `summary.txt` (가장 먼저)

진단 결과 1페이지 요약. 다음을 즉시 확인:

- **Verdict**: `정적 HTTP로 충분` / `JS 실행 필요` / `CLOUDFLARE_PROTECTED_SITE` / `BASELINE_BLOCKED`
- **진입 매트릭스**: `S1.H1~H4` / `S1.Hcap` / `S4` / `S5` / `S1L` / `Jina` / `Firecrawl` / `Crawl4AI` / 유료 4종 각각의 `OK`/`BLOCKED_BOT`/`BLOCKED_IP`/`LOGIN_REQUIRED`/`METHOD_INCOMPATIBLE`
- **권장 진입**: 도구가 추천한 가장 가벼운 통과 방식
- **권장 폴링 간격**: `robots.txt`의 `Crawl-Delay` 또는 보수치 5초
- **본문 진입 OK**: 첫 글 URL로 한 번 더 진입했을 때 통과 여부

### 3-2. `traffic.har` (Playwright 통과 시)

Chrome DevTools에서 바로 열린다(파일 드래그). HAR 안의 모든 request/response.
JSON XHR이 보이면 **글 데이터를 직접 호출하는 API 후보**일 가능성이 높다.

```bash
# 명령줄에서 빠르게 본다면
python -c "import json; har=json.load(open('output/probe/.../traffic.har', encoding='utf-8'));
for e in har['log']['entries']:
    mime = e['response'].get('content', {}).get('mimeType', '')
    if 'json' in mime or 'html' in mime:
        print(e['request']['method'], e['response']['status'], mime[:30], e['request']['url'][:120])"
```

### 3-3. `list.html` / `s1.H*.html`

목록 페이지 HTML. `BeautifulSoup`으로 직접 살펴 selector를 결정한다.

```python
from bs4 import BeautifulSoup
html = open('output/probe/.../list.html', encoding='utf-8').read()
soup = BeautifulSoup(html, 'lxml')
# 후보 selector 시도
print(len(soup.select('tr.ub-content')))   # 디시 마이너갤
print(len(soup.select('a.vrow.column')))   # 아카라이브
```

### 3-4. `list_candidates.json`

도구가 자동 추출한 **글 목록 후보 3종** (HTML 반복 패턴 / HAR JSON API / Hydration).
첫 글 URL이 같이 적혀 있다. 단, 광고나 다른 채널 anchor가 잡힐 수 있으니 *어댑터에서 host+board prefix로 한 번 더 거른다*.

### 3-5. `hydration.json` + 페이지 내 JS 번들

SPA(특히 Next.js)면 `__NEXT_DATA__`가 추출됨. 거기 글 데이터가 있으면 정적 httpx로 충분.
번들 JS 안에 API 패턴(`/api/foo/{id}`)이 있을 수 있어 grep도 유용하다 (엔드필드가 그 케이스였다).

## 4. Step 3 — 결과 해석

진단 매트릭스를 읽어 **어댑터 진입 전략**을 결정한다.

### 4-1. 의사결정 표

| Verdict / 매트릭스 패턴 | 어댑터 진입 |
|---|---|
| S1.H1~H4 일부 OK | **httpx 정적** (가장 약한 통과 프리셋 채택) |
| S1.Hcap만 OK, 나머지 S1 막힘 | **httpx + S4 캡처 헤더 그대로 주입** |
| HAR에 JSON API 후보 + Replay OK | **httpx로 그 API 직접 호출** (가장 가벼움) |
| Hydration JSON에 글 목록 발견 | **httpx로 메인 페이지 받아 `__NEXT_DATA__`만 파싱** |
| S4만 OK, 모든 정적 막힘 | **Playwright stealth 필수** |
| LOGIN_REQUIRED → S5 OK + S1L OK | **httpx + state.json 쿠키** (가벼움) |
| LOGIN_REQUIRED → S5 OK, S1L 실패 | **Playwright + storage_state 유지** |
| BLOCKED_GEO | 한국 IP 차단 채널 - 차단 우회 기술 조사.md 참고 |
| 모든 무료 막힘 + 유료 OK | 마지막 수단으로 유료 API 검토 |

### 4-2. 권장 폴링 간격

`robots.txt`의 `Crawl-Delay` 자동 추출 → 명시되어 있으면 그 값 이상.
없으면 **5초+ 보수치** + jitter ±30%.

### 4-3. 자주 마주치는 함정

- **빈 응답 200 (UA 필터)**: 디시처럼 헤더 없으면 0 bytes 반환. 도구는 BLOCKED_BOT으로 분류.
- **공지·광고 anchor**: 첫 글 URL 자동 추출이 다른 채널 광고를 가져올 수 있음. 어댑터에서 host+board prefix로 거른다.
- **상대 URL**: `href="/b/akendfield/123"` 같은 상대형. `urljoin`으로 절대화.
- **Cloudflare 사이트의 베이스라인**: `/`도 챌린지로 막히는 게 정상(IP 차단 아님). 도구는 `CLOUDFLARE_PROTECTED_SITE`로 표시.

## 5. Step 4 — 어댑터 작성

`adapters/<site>.py`에 새 어댑터를 만든다. `BaseAdapter`의 두 메서드만 구현하면 된다.

### 5-1. 인터페이스 (async)

어댑터는 모두 **async** 다 (`scripts/collect_all.py` 가 `asyncio.gather` 로 병렬 수집).

```python
from adapters.base import BaseAdapter, NoticePost

class XxxAdapter(BaseAdapter):
    site = "xxx.example"
    host = "xxx.example"          # 호스트 단위 lock 키 — collect_parallel 가 같은 host 직렬화
    polite_sleep_min = 2.0        # robots.txt Crawl-Delay 명시되면 그 값 이상으로 override
    polite_sleep_max = 5.0

    def __init__(self, *, board: str, **opts):
        self.board = board
        ...

    async def __aenter__(self):    # httpx.AsyncClient 또는 async_playwright 띄움
        ...
        return self
    async def __aexit__(self, *exc): ...

    async def fetch_list(self, *, page: int = 1, page_size: int = 30) -> list[NoticePost]:
        """게시판 1페이지의 글 목록 반환. content_html은 None으로 둔다."""
        ...

    async def fetch_article(self, post: NoticePost) -> NoticePost:
        """주어진 NoticePost에 본문(content_html)을 채워 새 객체 반환."""
        ...
```

`host` / `polite_sleep_min` / `polite_sleep_max` 클래스 변수 의미:

- `host` — `adapters/runner.py` 의 `collect_parallel` 가 **같은 host 어댑터를 자동 직렬화**한다. 같은 사이트의 다른 게시판 두 개를 동시에 등록해도 매너가 깨지지 않는 안전장치. 다른 사이트는 동시 실행됨.
- `polite_sleep_min/max` — `await self.polite_sleep()` 의 기본 간격. 기본 2~5초. dcinside 처럼 robots.txt 가 30초를 명시하면 클래스 변수로 30/35 override.

`NoticePost` 필드(고정):

```
site, board, post_id, title, url, published_at(ISO8601), author, category,
summary, content_html, cover_image, raw(dict — 사이트 원본 보존)
```

### 5-2. 진입 방식별 골격

**A. httpx (정적 HTML)** — 디시 패턴

```python
HEADERS = {"User-Agent": "Mozilla/5.0 ... Chrome/124.0.0.0 ..."}

async def __aenter__(self):
    self._client = httpx.AsyncClient(headers=HEADERS, timeout=15.0, follow_redirects=True)
    return self

async def __aexit__(self, *exc):
    if self._client is not None:
        await self._client.aclose()
        self._client = None
```

**B. httpx (JSON API)** — 엔드필드 패턴

```python
# 필요 시 Origin/Referer 추가
HEADERS = {..., "Origin": "https://xxx.example", "Referer": "https://xxx.example/"}
r = await self._client.get(API, params={...})
data = r.json()["data"]["list"]
```

**C. Playwright stealth** — 아카라이브 패턴

```python
from playwright.async_api import async_playwright
from playwright_stealth import Stealth

async def __aenter__(self):
    self._pw = await async_playwright().start()
    self._browser = await self._pw.chromium.launch(headless=True)
    ctx_kwargs = {"viewport": {...}, "locale": "ko-KR", "user_agent": UA}
    if self.state_path and Path(self.state_path).exists():
        ctx_kwargs["storage_state"] = str(self.state_path)
    self._context = await self._browser.new_context(**ctx_kwargs)
    await Stealth().apply_stealth_async(self._context)
    self._page = await self._context.new_page()
    return self
```

### 5-3. 일반 규칙

- **`async with` 컨텍스트 사용** — fetch_list/article 사이 세션·브라우저 재사용
- **`host` 클래스 변수 채울 것** — 빠뜨리면 `collect_parallel` 의 lock 키가 site 로 fallback 되어 같은 host 두 어댑터를 못 묶음
- **본문 순회 사이 `await self.polite_sleep()`** — 인자 없음. 어댑터 자기 간격 사용
- **`raw` 필드에 사이트 원본 보존** — 새 필드가 필요할 때 어댑터 인터페이스 안 깨짐
- **`published_at` ISO8601 정규화** — 사이트별 형식이 다양함
- **공지/광고 분리** — 사이트별로 클래스 이름 다름. probe로 미리 확인
- **공식 사이트에 글 단독 URL이 없으면** `url`은 `None` (엔드필드처럼 SPA 모달인 경우)

## 6. Step 5 — 데모로 검증

`scripts/demo_<site>.py`를 만들어 직접 호출. 산출물을 `output/adapter/<site>/`에 raw로 저장.

### 6-1. 데모 골격

```python
import asyncio
import json
import sys
from pathlib import Path

# 프로젝트 루트를 sys.path에 추가 (scripts/에서 패키지 import)
sys.path.insert(0, str(Path(__file__).resolve().parent.parent))

from adapters import XxxAdapter

OUT = Path(__file__).resolve().parent.parent / "output" / "adapter" / "xxx"
OUT.mkdir(parents=True, exist_ok=True)


async def main():
    async with XxxAdapter(board="...") as a:
        posts = await a.fetch_list(page=1, page_size=30)
        print(f"{len(posts)}건 수신")
        (OUT / "list.json").write_text(
            json.dumps([p.to_dict() for p in posts], ensure_ascii=False, indent=2),
            encoding="utf-8",
        )
        for i, p in enumerate(posts[:3]):
            await a.polite_sleep()
            full = await a.fetch_article(p)
            print(f"  [{i+1}] {full.post_id}  body={len(full.content_html or '')} chars  {full.title[:50]}")
            (OUT / f"article_{full.post_id}.json").write_text(
                json.dumps(full.to_dict(), ensure_ascii=False, indent=2), encoding="utf-8"
            )
            (OUT / f"article_{full.post_id}.html").write_text(full.content_html or "", encoding="utf-8")


if __name__ == "__main__":
    asyncio.run(main())
```

### 6-2. 검증 체크리스트

- [ ] `fetch_list` 결과 건수가 사이트 화면 기준과 비슷한가
- [ ] 광고/타 채널 항목이 섞여 있지 않은가
- [ ] `post_id`가 *고유 정수/문자열*인가 (새 글 감지에 쓸 수 있어야 함)
- [ ] `published_at`이 ISO8601로 들어갔는가
- [ ] `fetch_article`이 본문 길이 ≥ 100 chars
- [ ] `content_html`이 사이트 헤더/푸터 같은 노이즈를 포함하지 않는가
- [ ] `with` 종료 후 자원이 정리되는가 (httpx.Client.close, browser.close)

## 7. 어댑터 5종 참고표 (현재 작업물)

| 어댑터 | host | 진입 | polite_sleep | 특이 |
|---|---|---|---|---|
| **EndfieldAdapter** (`adapters/endfield.py`) | `web-news.gryphline.com` | httpx + JSON API (`/api/bulletin`) | 2~5s | `Origin`/`Referer` 필수, cid leading zero 4자리 |
| **DCInsideMGalleryAdapter** (`adapters/dcinside.py`) | `gall.dcinside.com` | httpx + bs4 (HTML) | **30~35s** (robots Crawl-Delay) | `tr.ub-content.us-post`(일반) vs `tr.ub-content`(공지/광고) |
| **ArcaLiveAdapter** (`adapters/arca.py`) | `arca.live` | Playwright stealth | 2~5s | Cloudflare 보호, `?category=...` 지원, 성인은 `state_path` |
| **SkkuCseAdapter** (`adapters/skku_cse.py`) | `cse.skku.edu` | httpx + bs4 (HTML) | 2~5s | `?srCategoryId1=1582` (학부 공지) |
| **NaverCafeAdapter** (`adapters/navercafe.py`) | `naver.com:cafe` (논리키) | httpx + JSON API (apis.naver.com / article.cafe.naver.com) | 2~5s | 401/403 회원 전용 글은 본문 비워서 반환 |

## 8. 막힐 때 체크리스트

| 증상 | 점검 |
|---|---|
| `fetch_list`가 0건 | selector를 *어댑터가 받은 HTML*에 직접 `BeautifulSoup`으로 시도. probe HTML과 다를 수 있다(쿠키/state 영향) |
| 401/403가 자주 뜬다 | UA 외 헤더 빠짐(특히 `Origin`/`Referer`). probe `s4.captured_headers.json` 확인 |
| 본문이 빈 SPA shell | Hydration JSON에 데이터가 있는지 `hydration.json` 다시 확인. 또는 클라이언트 측 fetch가 있는지 `traffic.har` 재검색 |
| Cloudflare 챌린지 | Playwright 필수. cf_clearance는 정적 세션에 안 옮겨짐(S1L 막힘이 검증) |
| Crawl-Delay 무시했더니 차단 | `robots.json`의 `crawl_delay` 따름. 어댑터 클래스의 `polite_sleep_min/max` 늘림 |
| 광고가 첫 글로 잡힘 | 어댑터에서 host+board prefix로 거른다(`probe_main`은 일반 도구라 못 거름) |
