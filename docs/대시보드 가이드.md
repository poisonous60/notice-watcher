# 대시보드 가이드

dev 박스 전용 로컬 웹 대시보드 (`scripts/dashboard.py`). 1인 운영용 — 인증 X, `127.0.0.1:8765` 만 바인딩, 외부 노출 절대 금지.

## 1. 띄우기

```powershell
# 최초 1회 의존성 설치
pip install -r requirements-dashboard.txt

# 실행
python scripts/dashboard.py             # 기본 127.0.0.1:8765
python scripts/dashboard.py --reload    # dev — 파일 변경 자동 reload (권장)
```

브라우저: <http://127.0.0.1:8765>

종료: Ctrl+C.

## 2. 데이터 모델 — Pull → snapshot → 표시

봇·폴링은 N100 미니PC 에서 돈다. 대시보드는 직접 N100 을 보지 않고 **로컬 snapshot 사본**을 본다.

- 상단 **🔄 Pull from N100** 버튼 = `scripts/inspect_subs.py pull` 실행
- N100 의 `bot.sqlite3` / `usage.sqlite3` / `configs/*.json` / `output/poll_state/*.json` 을 `output/snapshot/` 에 떨굼 (SQLite 는 `.backup` 으로 일관성 사본)
- 페이지 새로고침 → snapshot 최신화

snapshot 시각은 페이지 상단에 표시. 오래되면 Pull 다시 누르면 됨.

## 4. `/usage` — 모델 사용량

`output/usage.sqlite3` (Pull 로 떨군 사본) 위에서 read-only 집계.

뷰 구성:

- **KPI 카드** — 호출 수 / 총 토큰 (in+out 분리) / 비용 ($) / avg latency / 에러율
- **일별 토큰 추세** — chart.js 라인 차트. call_site 별 컬러
- **call_site × model 매트릭스** — 어느 모델이 어디서 얼마 썼나. **모델 비교 핵심 뷰**
- **최근 호출** — raw 행 (ts/call_site/model/status/tokens/latency/cost/attempt). slug 클릭 시 sub 상세로

필터:

- 범위: 오늘 / 최근 7일 / 최근 30일 / 전체
- call_site: 4 종 (`config_generate`, `config_retry`, `notify_summarize`, `notify_filter`)
- 최근 N행: 10~1000

비용 계산:

- Gemini / OpenRouter 둘 다 응답에 직접 비용 안 줌
- `model_prices.json` 의 단가 (per 1M tokens) × 토큰 수로 산출
- 가격표에 없는 모델은 `cost_usd` = `—` (그 외 필드는 정상)

## 4-bis. `/users` — 사람 단위 목록 + scoped announce + debug replay

slug 단위 (`/subs`) 와 평행한 **사람 단위** 진입점. 같은 사용자가 어떤 slug 들을 어떻게 받고
있고 무슨 feedback/report 를 남겼는지를 한 화면으로 본 뒤, 좁힌 공지 발송이나 디버그용
재발송을 한다.

### 4-bis.1 user set 정의

distinct user_id 집합 = `subscriptions ∪ feedback ∪ reports ∪ jobs.requested_by.id`.
즉 `/watch` 만 한 사용자, `/preview` 만 한 사용자 (jobs.requested_by), `/feedback` 만
남긴 사용자, `/report` 만 한 사용자 모두 잡힘. username 은 latest feedback / reports /
jobs.requested_by.name 중 비어있지 않은 첫 값 (셋 다 없으면 `<id only>` 표시).

### 4-bis.2 목록 (`/users`)

검색 + chip 필터 + 정렬 + multi-select.

- **검색**: user_id · username 부분 일치.
- **chip 필터**: open report 있음 / has feedback / has channel sub.
- **slug 필터**: 자동완성 dropdown — 그 slug 를 어떤 형태로든 구독한 사람만.
- **정렬**: 컬럼 header 클릭 → ASC/DESC 순환. default `last_active` DESC.
- **컬럼 가시성 토글**: `<details>` 안 checkbox + `/settings` 의 동일 섹션. **localStorage**
  (`dashboard.users.cols`) — 브라우저별 분리, privacy 모드선 안 남음.
  default cols = `user_id · username · n_subs · last_active`. 추가 가능:
  `n_dm_subs / n_channel_subs / sources / n_feedback / n_reports_open(total) /
  first_seen / total_deliveries / last_delivery_at`.
- **multi-select**: 행 체크박스 → 상단 **"선택한 N명에게 공지"** 버튼 → 공지 모달.

### 4-bis.3 상세 (`/users/<id>`)

S3 hybrid 레이아웃 — 사람 = entity, 채널 = 라우팅 선택.

- **DM 구독**: slug · URL · filter prompt · created · **액션 셀**
  - `expand` — 그 (user, slug) 의 deliveries 최근 50건 inline (HTMX). post 별 `M2 replay` 버튼.
  - `M1 poll` — 이 slug 즉시 polling (다른 구독자도 영향).
  - `M3 bulk` — 이 (user, slug) 첫페이지 강제 재발송 (이 user 만).
- **채널 구독**: 별도 섹션, 노란 경고 배너 ("M2/M3 replay 도 채널 전체에 발송 — user
  격리 없음"). M1 + M3 활성.
- **Feedback / Reports / Jobs / Recent deliveries**: 각각 user 별 상세 표시.
- **우상단 "이 user 에게 공지"**: 단일 user prefill 된 공지 모달.

### 4-bis.4 Scoped announce (= `/admin announce` 의 확장)

기존 `/admin announce` 가 전체 broadcast 인 반면, dashboard 의 announce 는 **recipient
chip 리스트** 로 좁혀 보냄. recipient 추가 경로:

1. `/users` 의 체크박스 multi-select → DM recipient 로 prefill.
2. 모달의 **"slug 으로 구독자 추가"** — csv 입력 → 그 slug 들의 모든 `(target_kind,
   target_id)` 자동 resolve (DM + channel 둘 다).
3. **"직접 ID 추가"** — `dm:<user_id>` / `channel:<channel_id>` 수동 paste.

옵트아웃 (`announce_prefs.opted_out=1` 한 user / channel) 은 발송 단계에서 자동 제외
+ `optout_skipped=N` 카운트 표시. 강제 발송 옵션 없음.

전송 경로:

- dashboard → JSON 페이로드 (`title`, `message`, `recipients[][kind,id]`) → **base64
  인코딩** → `scripts/remote.py announce-scoped <b64>` 가 SSH 로 N100 의
  `scripts/announce.py --base64 <b64>` 실행. base64 인코딩이 SSH command line shell
  injection 차단.
- N100 측 `scripts/announce.py` 가 BOT_TOKEN REST 로 DM/채널 직접 발송 (게이트웨이
  봇 프로세스 거치지 않음 — notify.py 와 동일 패턴).

Audit: `announcements` 테이블에 row 1개 + `recipient_targets TEXT` 컬럼 (JSON
`[[kind,id], ...]`). NULL = legacy broadcast 의미.

### 4-bis.5 Debug replay (M1 / M2 / M3)

특정 user 가 받았어야 할 글이 안 갔거나, 검증을 위해 같은 글을 다시 받게 하고 싶을 때.

| 모드 | 동작 | 영향 범위 |
|---|---|---|
| **M1 poll** | `poll.py --sites <slug>` 만. seen/deliveries 안 건드림. | 새 글 있으면 **모든 구독자** 발송. 디버그용 즉시 polling. |
| **M2 replay** (post 행별) | `deliveries` 1행 + `seen_post_ids` 1개 제거 → poll-now → notify `--only-target`. | **이 user 만** 그 post 재발송. 정밀. |
| **M3 bulk** | (user, slug) deliveries **전체** + `seen_post_ids` 통째 비움 → poll-now → notify `--only-target`. | **이 user 만**, 사이트 첫페이지의 *모든* 글 재발송. |

전송 경로:

- dashboard → `scripts/remote.py replay-deliveries <slug> <kind> <id> [post_id]` SSH →
  N100 의 `scripts/replay.py` 가 lock 잡고 직렬 실행.
- replay.py 가 `systemctl --user is-active notice-poll.service` + `pgrep` 으로 poll 중인지
  pre-check → 활성이면 fail-fast (state 파일 race 차단). `output/.replay.lock` 을
  `O_EXCL` 로 잡음 (동시 replay 차단).

**한계 — 본문 영구저장 없음**:

- poll_state.seen_post_ids 에 그 post_id 가 있어야 fetch_list 결과의 NEW 판정에서 다시
  잡힘. 사이트 첫페이지에서 글이 내려갔으면 영원히 못 잡음. preview modal/expand
  panel 에 `evicted` 배지 + 경고 표시.
- 임의 시점의 옛 글 본문 정밀 재발송이 필요하면 별도 PR 로 `posts(slug, post_id,
  payload_json, fetched_at)` 테이블 신설 필요 — 현 구현엔 없음.

### 4-bis.6 새 remote.py verb 들

`scripts/remote.py list` 로 확인 가능.

```
poll-now-slug <s1,s2,...>                      부분 poll-now
replay-deliveries <slug> <kind> <id> [post]    M2/M3 replay
notify-target <slug> <kind> <id>               collected → 그 target 만 발송
announce-scoped <base64-json>                  좁힌 공지 발송
```

모두 인자별 정규식 검증 (`_SLUG_RE`, `_TARGET_ID_RE`, `_POST_ID_RE`, `_BASE64_RE`).
N100 helper 호출 = `cd $DEPLOY_PATH && .venv/bin/python scripts/<helper>.py …`
(venv python 명시 — system python 엔 httpx 없음).

## 5. `/control` — 운영 제어

저장 = 로컬 staging 파일 작성 + 즉시 `scp` 로 N100 에 push (필요 시 systemctl 자동 호출).

5 섹션 collapsible (`<details>`):

### 5.1 Model routing

call_site → `provider:model` 매핑. `output/llm_routing.json` 에 저장 → N100 mtime 캐시가 다음 LLM 호출에서 자동 재로드 (재시작 X).

- 행 5 개: 4 call_site + `_default`
- 드롭다운 옵션은 `model_prices.json` 에서 자동 로드. "custom..." 선택 시 직접 입력 (새 모델 테스트)
- 빈 값 = 그 매핑 제거 → `_default` 사용 → 그것도 없으면 `GEMINI_MODEL` env 또는 `gemini-2.5-flash`
- 각 행 뱃지:
  - `override` (녹색) — 명시 매핑 있음
  - `default` (회색) — 매핑 없음, fallback 사용 중 (어느 모델인지 select 옆에 표시)

저장 흐름: validate (JSON 형식 + 알 수 없는 provider 거부) → 로컬 `output/llm_routing.json` 쓰기 → `scp` push. push 실패 시 로컬 자동 rollback.

### 5.2 Runtime tuning

`config.toml` (repo default) 위에 덮어쓰는 머신별 override. **변경 후 봇/폴링 재시작 필요** ("저장 후 봇 재시작" 체크박스).

11 필드 (섹션별):

| 섹션 | field | default | 무엇 |
|---|---|---|---|
| poll | concurrency_httpx | 8 | httpx 폴링 동시 요청 |
| poll | concurrency_chromium | 1 | chromium 폴링 동시 |
| poll | page_size | 30 | 한 페이지 글 수 |
| poll | max_new_articles | 10 | 한 사이클 최대 새 글 |
| poll | breakage_threshold | 2 | 연속 실패 임계 (이후 FAILED) |
| poll | seen_cap | 5000 | seen post id 상한 |
| worker | idle_poll_seconds | 2.0 | 워커 idle 주기 |
| chromium_lock | bot_timeout | 900.0 | 봇 chromium lock 타임아웃 |
| chromium_lock | poll_timeout | 1800.0 | 폴링 chromium lock 타임아웃 |
| chromium_lock | register_subprocess_timeout | 600.0 | register 서브프로세스 타임아웃 |
| notify | delivered_cap | 5000 | delivered id 상한 |

빈 입력 = default 유지. default 와 같은 값 입력 = 자동 생략 (TOML 깨끗). 잘못된 숫자 → 서버에서 인라인 에러.

저장: validate (tomllib parse) → 로컬 `config.local.toml` 쓰기 → push → (선택) `systemctl --user restart notice-bot.service`.

### 5.3 Environment (.env)

N100 의 `.env` 직접 편집. **비밀 포함** — `BOT_TOKEN`, `GEMINI_API_KEYS`, `OPENROUTER_API_KEY` 등.

흐름:
1. 상단 **⬇ N100 에서 .env · timer 읽기** 한 번 클릭 (SSH `cat .env`)
2. textarea 가 채워짐. 기본 입력 마스킹 (`●●●●●●`)
3. **Reveal** 체크박스로 표시/감춤 토글
4. 편집 후 **💾 Save & Push (.env)** — confirm 다이얼로그 뜸
5. (선택) "저장 후 봇 재시작" 체크 → `restart-bot` 도 같이 실행

안전장치:
- 활성 `BOT_TOKEN=` 행이 없으면 저장 거부 (주석 처리된 `# BOT_TOKEN=` 은 카운트 X) — 부분 텍스트 push 실수 차단
- `.env.push` staging 파일은 push 완료/실패 무관하게 `finally` 에서 삭제 — 비밀이 dev 박스에 잔류 X
- 단방향: dev 박스 자신의 `.env` 는 절대 N100 에 안 감 (별도 `.env.push` 만)

### 5.4 Poll schedule

`notice-poll.timer` 의 `OnCalendar=` 값 편집. 현재 매일 08:20 KST.

- 상단 ⬇ 버튼으로 N100 timer 읽기 (위 .env 와 같이 로드됨)
- `OnCalendar=` 한 줄만 인풋. 프리셋 링크: 매일 08:20 / 매일 18:00 / hourly / 30분마다 (테스트)
- 저장: validate (regex — 영숫자·`*`·`:`·`-`·`,`·`/` 만 허용, 줄바꿈 차단) → 원본 timer 의 `OnCalendar` 줄만 교체해서 push → N100 `daemon-reload` 자동 → (선택) status + 로그 표시

저장 후 다음 cron 슬랏부터 적용. 즉시 1회 돌리려면 5.5 의 **▶ Poll now**.

### 5.5 Remote commands

N100 의 systemd 유닛에 명령을 SSH 로 보낸다. 모든 명령은 allowlist — 임의 shell 실행 X.

| 버튼 | 명령 | 무엇 |
|---|---|---|
| ▶ Poll now | `systemctl --user start notice-poll.service` | 폴링 사이클 즉시 1회 실행. 다음 timer 슬랏 안 기다림 |
| 🔁 Restart bot | `systemctl --user restart notice-bot.service` | Discord 봇 재시작. 게이트웨이 ~5초 끊김 — confirm 다이얼로그 |
| ↺ daemon-reload | `systemctl --user daemon-reload` | unit 파일 직접 손으로 바꿨을 때. 보통 timer push 가 자동 호출하니 따로 안 눌러도 됨 |
| ⏵ status (unit) | `systemctl --user status <unit>` | active/inactive·최근 종료 코드·메모리 등 — read-only |
| 📜 logs (unit, tail) | `journalctl --user -u <unit> -n <tail>` | 해당 유닛 stdout/stderr 로그 |

unit 알리아스:

| alias | systemd unit | 무엇 |
|---|---|---|
| `bot` | `notice-bot.service` | Discord 게이트웨이 상주. 슬래시 명령 (`/watch`, `/report`, `/admin`) 처리 |
| `poll` | `notice-poll.service` | 매일 (또는 timer 가 깨우면) 등록된 모든 사이트 fetch → 새 글 검출 |
| `poll-timer` | `notice-poll.timer` | 위 service 의 cron 트리거 (`OnCalendar`) |
| `notify` | `notice-notify.service` | poll 결과 받아 Gemini 요약 + Discord 발송 |

로그에 보이는 전형:
- **bot**: 게이트웨이 connect/disconnect, 슬래시 명령 처리, `register.py` 서브프로세스 spawn, `make_example` 진행, Discord API 실패, `[gemini] 키 #N/5 quota 소진(429)`
- **poll**: 사이트별 fetch 결과, 새 글 N개, breakage 누적, FAILED 마킹
- **notify**: 요약 생성, 필터 통과/거부, DM/채널 발송 성공/실패, heartbeat 송신

## 6. Audit log

`/control` 의 모든 save·remote 명령은 `output/control_audit.jsonl` 에 한 줄씩 append. 비밀 값은 기록 X (`size`, `keys 이름`, `rc` 만).

```bash
tail output/control_audit.jsonl | jq .
```

용도:
- "언제 routing 바꿨지" → grep `save.routing`
- "왜 봇이 갑자기 pro 로 갔지" → 직전 routing.json 변경 확인
- "push 실패 빈도" → `grep '"ok":false' | wc -l`

## 7. 인접 도구 — 손으로 쓸 일

대시보드가 못 하는 작업은 CLI 로:

- `python scripts/remote.py list` — 같은 식 remote 명령 목록

- `python scripts/triage.py` — 자동 등록 실패 (`.FAILED.json`) triage 큐 dump

- **127.0.0.1 만 바인딩**. 절대 `0.0.0.0` 으로 띄우지 말 것 (`scripts/dashboard.py` 가 default 127.0.0.1 강제)
- 인증 없음 — localhost 접근 = 곧 dev 박스 사용자 == 너 가정
- `.env` 편집 시 텍스트 입력은 기본 마스킹. Reveal 누를 때만 표시
- N100 SSH 키는 `~/.ssh/` 에 있다는 가정 (`scripts/inspect_subs.py` 와 동일)
- push/remote 모두 allowlist — slug·command·path 자유 입력 차단

| 증상 | 원인 / 조치 |
|---|---|
| `/usage` 가 "스냅샷 없음" | 한 번도 Pull 안 함. 또는 N100 에 아직 LLM 호출 0회. 🔄 Pull 누름 |
